## 3. 배너 저장과 API 계약

### 저장 모델

`gnu_jango.shop.models.ShopBanner`를 새 관리 대상으로 둔다.

| 필드 | 용도 |
|---|---|
| `bn_id` | 자동 증가 식별자 |
| `bn_alt`, `image_url`, `bn_url` | 대체 텍스트, 공개 이미지 경로, 클릭 목적지 |
| `bn_position`, `bn_device` | 위치 및 `both`/`pc`/`mobile` 노출 대상 |
| `bn_order`, `is_active` | 노출 순서와 운영 상태 |
| `begin_at`, `end_at` | 게시 시작/종료 시각. 비어 있으면 해당 경계 없이 노출 |
| `bn_border`, `bn_new_win` | 기존 영카트 배너 호환 옵션 |
| `hit_count` | 공개 클릭 경로의 집계 값 |

Django 관리자 URL은 `/admin/shop/shopbanner/`다. 이미지를 파일로 업로드하지 않고 URL 또는 `/data/banner/{bn_id}` 경로를 관리한다. 기존 가져오기 명령은 `g5_shop_banner_table`을 읽어 기간·순서·클릭 수와 `/data/banner/{bn_id}` 경로를 저장한다.

### 공개 조회와 클릭

- `GET /api/v1/shop/banners?position=메인&device=all`: 활성화·기간·위치에 맞는 배너를 `bn_order`, `bn_id` 오름차순으로 반환한다.
- `device=pc|mobile`은 해당 기기용 배너와 `both` 배너를 포함한다. `all`은 기기 구분 없이 조회한다.
- 응답은 현재 프런트 계약의 `bn_id`, `bn_alt`, `bn_url`, `bn_position`, `bn_device`, `bn_border`, `bn_new_win`, `bn_order`, `image_url`, `hit_url`을 유지한다.
- 기존 클릭 주소 `/shop/bannerhit.php?bn_id=…`는 Django API에서 목적지/집계를 조회한다. 프런트 route bridge는 상대 주소와 HTTP(S) 주소만 허용하고, 브라우저 쿠키를 통해 하루 한 번 집계 요청을 보낸다.
- 상점 페이지는 서버 API에서 데이터를 받아 현재 300초 revalidate 설정을 따른다. 관리자 수정은 코드/테마 빌드가 아니라 저장 데이터로 반영한다.

## 4. 상품 데이터 표시 계약

- 상품 이미지가 없으면 API는 빈 URL과 빈 이미지 목록을 보낸다. 카드·목록·상세는 상품용 아이콘과 “상품 이미지 없음” 안내를 보여준다. 사이트 앱 아이콘을 상품 사진처럼 표시하지 않는다. 홈 카드는 실제 후기가 있는 상품에만 평점/후기 수를 표시하고, 옵션이 없고 재고가 있는 상품에만 바로 담기를 제공한다.
- `it_brand`, `it_maker`, `it_origin`, `it_model`, `it_basic`은 Django `ShopProduct`, 상품 API payload, `migrate_gnuboard5` 가져오기에서 같은 이름으로 보존한다. 상세는 브랜드, 상품명, 부제 순으로 표시하고 제조사·원산지·모델명은 값이 있을 때만 상품 정보 목록에 넣는다. 비어 있는 값을 임의로 보충하지 않는다.
- 상품 가져오기는 상품 기본값을 갱신해도 기존 옵션 목록을 빈 배열로 덮어쓰지 않는다. 원본 옵션 데이터는 별도 옵션 가져오기 경로에서만 갱신한다.
- `ShopProduct.it_option_subject` 및 `it_supply_subject`에 기존 영카트의 옵션명/추가 옵션명을 보존한다. 기존 DB 가져오기는 원본 필드를 저장하고 관리자에서 보완할 수 있다.
- 원본 옵션명이 비어 있고 선택 옵션 데이터는 존재하는 레코드에는 `선택 옵션 N`으로 기능상 구분을 유지한다. 값이 있는 원본 이름은 항상 그대로 사용한다.
- `ShopProduct.it_hit`에 원본 조회 수를 가져온다. 홈의 인기/추천/신상품/할인 행과 상품 목록의 유형·가격 필터가 같은 상품 집합을 반복하지 않도록 `it_type1..5`, 최신/가격 정렬을 API에 연결한다.
- 상세 데이터 GET은 정적 생성·캐시에서도 호출되므로 조회수를 바꾸지 않는다. 실제 상세 화면이 열린 뒤 브라우저가 `POST /api/v1/shop/products/{it_id}/hit`를 보낸다. API는 같은 세션에서 같은 날짜의 같은 상품 조회를 한 번만 기록하며, 세션에는 최근 100개 상품 ID를 보관한다. `sort=popular`는 이 누적 조회수를 사용한다.
- 전체 구매 패널의 이전/다음 상품 링크는 구매 동작 뒤, 상세 탭 앞에 둔다. 고정형 보조 구매 패널에는 이전/다음 링크를 반복하지 않는다.
- 제품 재고·구매 제한·옵션 금액 계산은 기존 서버 검증과 클라이언트 훅을 유지한다.

## 5. 게시판 목록/상세

- 목록·상세는 `.solune-content-shell`의 본문 + 우측 레일 구조를 공유한다. 1024px 미만에서는 한 열로 바꾼다.
- 본문은 `minmax(0, 1fr)` 단일 grid 열을 사용해 긴 제목·본문 이미지가 화면 폭을 늘리지 않게 한다. 목록 표의 번호/작성자/조회/날짜 열은 1024px 미만에서 접고 제목 아래 요약 행으로 제공한다.
- 목록 제목 아래에 글 수/현재 페이지를 두고, 공지와 일반 행, 쪽 이동은 현재 게시판 데이터를 계속 사용한다. 검색 폼은 목록 뒤에 놓아 첫 화면의 표와 레일을 기준 화면에 가깝게 보인다.
- 글 상세 제목은 줄바꿈 가능한 전체 폭을 쓴다. 작성자/날짜/조회/분류/공유 정보를 묶고, 수정·반응·댓글·이전/다음 글과 목록 동작을 유지한다. 노출 텍스트는 한국어로 통일한다.
- 댓글과 이전/다음 글 아래에는 현재 게시판의 최신 글(분류가 있으면 같은 분류)을 최대 5개까지 보여주고, 전체 목록으로 연결한다.
- 수정·삭제 등 권한은 기존 API와 `PostActions` 판정을 유지한다. rail은 로그인 여부에 따라 별도 로그인 폼 또는 회원 정보를 보인다.

| 폭 | 상점 홈 | 게시판 |

## 7. 남은 결정과 검증

- 기준 시각 수용은 같은 데이터와 역할, 같은 viewport에서 화면의 구조·색상·주요 기준점 차이를 측정한 뒤 판정한다. 현재 기준 사이트와 로컬의 게시글/상품 데이터가 다른 경우 해당 차이는 레이아웃 합격 근거로 사용하지 않는다.
- 상점 홈 390px에서 분류 카드(x16, y386, 172×128)와 히트상품 섹션(x16, y568), 768px에서 첫 카드(x24, y523, 231×146)와 히트상품 섹션(x24, y722), 1440px에서 첫 카드(x112, y845, 109×146)와 상품 섹션(x112, y1045)이 기준에 맞는다. 상점 헤더는 원본 영카트 PNG 로고, 카테고리 버튼, 상품 유형 링크와 원형 아이콘을 적용했다. 768px 카테고리 버튼은 x196/y57/101×40, 1440px은 x304/y57/101×40이며, 1440px 검색·회원·장바구니 버튼의 x좌표는 1196/1243/1290이다. 390px에서 document 폭은 viewport와 같다.
- 같은 상품 ID 1446772772 상세는 767px 이하 한 열, 768px부터 기준처럼 두 열로 배치한다. 390px에서 갤러리 x16/y192/358×358, 제목 y704, 부제 y793, 평점 y823, 가격 y889를 확인했다. 768px에서 갤러리 x24/y204/356×356, 구매 패널 x420/y204/w324, 제목 y234/h75이며 기준과 각 열이 약 1px 차이다. 1440px에서는 구매 패널 x888/y204/w440, 제목 y234, 부제 y332, 평점 y364, 가격 y434다. 옵션 품절/오류와 보조 구매 패널 상태는 기능 수용을 계속한다.
- 실제 media 경로와 배포 정적 호스트에서 이미지가 계속 열리는지 확인한다. 현재 검증은 로컬 개발 환경이며 결제 실행은 포함하지 않는다.
- 원본 서버 8081은 중지하지 않았다. 최신 HTML이 8081에서 200과 새 정적 chunk를 반환하는 것을 확인했지만, 게시글·댓글·카트 저장 동작은 격리 DB 8082에서만 검증했다.

## 8. 2026-10-08 런타임 확인

- npm run build:theme가 통과했고 정적 경로 1,074개를 생성했다. Django 템플릿/정적 테마 2,320개 파일이 빌드 결과와 일치한다.
- 격리 DB 대상 Django check에서 오류가 없었고 makemigrations --check --dry-run은 변경 사항이 없다고 응답했다.
- 1440×900, 768×1024, 390×844에서 주요 화면을 캡처했다. 각 target 화면의 document 폭은 viewport 폭과 같았다.
- 복제 서버에서 RSS 비활성/비공개는 링크 0개와 HTTP 404, 공개는 링크 1개와 HTTP 200을 반환한 뒤 원래 설정으로 복구했다.
- 게시판 역할별 입력 폼과 서버 권한을 확인했다. 제한 권한 쓰기/댓글은 HTTP 403, 게시판 관리자/회원 댓글은 HTTP 201이며 회원 댓글은 새로고침 뒤에도 남았다.
- 상품 상세 SIZE=L, COLOR=그레이 선택이 두 구매 패널에 동기화됐다. 카트 POST는 HTTP 201, 카트에 옵션과 31,000원 상품 금액/3,000원 배송비가 표시되고 주문 화면에 진입했다. 결제는 제출하지 않았다.
- 캡처와 브라우저 증거는 gitignored 경로 .tmp-nextjs-runtime/subpage-final-acceptance-20261008에 저장했다.
- 최신 홈 보정 뒤에도 1,074개 경로 정적 빌드와 2,320개 파일 동기화가 통과했다. `/shop`은 격리 서버 8082 및 원본 서버 8081에서 HTTP 200이며, 8081 응답에 현재 빌드의 `app/shop/page-0384f04c8de4c312.js`와 `c33bff99e7abcaf5.css`가 포함된다.
- 390/1440px의 카테고리 카드와 히트상품 시작점은 기준 DOM 좌표와 일치한다. 768px 홈도 document 폭 768px이며 카테고리·상품 행을 보여준다. 화면 캡처는 `.tmp-nextjs-runtime/subpage-final-acceptance-20261008/target-shop-mobile-pass-*` 및 `target-shop-tablet-768.png`에 있다.

## 9. 2026-10-08 게시글 상세 최신 코드 재검증

- 별도 복제 DB를 사용하는 8087 런타임에서 `/free/3999`를 다시 캡처했다. 기준 #219와 대상 #3999는 제목·본문·작성자·작성일·첨부명·댓글 수가 같은 콘텐츠 fixture이며 레코드 ID와 조회 수는 다르다.
- 상세 카드 좌표는 390px `x16/y224/w358`, 768px `x24/y224/w720`, 1440px `x112/y232/w896`였다. 기준과 비교하면 768px의 y좌표만 1px 차이이며 document 너비는 세 화면에서 viewport와 같다.
- 원본 첨부 파일이 없어 두 첨부 링크는 `원본 파일 없음` 상태로 표시되고, 아바타는 초기 글자 fallback을 사용한다. 브라우저 오류는 없었다. 캡처와 전체 자산 감사 결과는 `docs/03-analysis/nextjs-default-subpages.audit.md` 27절에 기록했다.

## 12. 2026-10-14 전체 서브페이지 구조

- CSS: 레퍼런스 CSS는 그대로 복사하고(`solune-theme.*.css`, `solune-shop.*.css`), 앱 전용 보정은 `solune-shop.app{,-purchase,-browse}.css`, `solune-theme.app-mypage.css`로 분리해 `solune-theme.css`에서 불러온다. 쇼핑 규칙은 `.solune-shop-page`로 범위를 좁히므로 쇼핑 레이아웃은 `main#main-content.shop-content`를 그린다.
