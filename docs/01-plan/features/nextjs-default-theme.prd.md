## 1. 제품 목표

**2026-10-08 수용 범위 정정:** 홈 화면 QA와 경로/기능 확인을 전체 테마 디자인 완료로 확대하지 않는다. 쇼핑몰 홈·상품 상세·게시판 목록·글 상세의 구조 차이와 모바일 정보 부족은 [서브페이지 개선 PRD](nextjs-default-subpages.prd.md)에서 P0 미완료로 관리한다. 이 문서의 기존 기능·설치/복구 확인 기록은 유지하며 FR-03/04/07/10의 서브페이지 디자인 수용 조건은 후속 PRD로 보완한다.

그누보드5 참고 프로젝트의 커뮤니티·회원·쇼핑몰 사용자 경험을 Django 환경에서 사용할 수 있는 `nextjs_default` 테마로 제공한다. 개발자는 `nextjs/`에서 화면을 수정하고 빌드하며, 운영자는 Django의 테마 선택과 설정을 통해 화면을 적용한다.

소스명, 배포 테마명, 표시 브랜드를 각각 관리한다.

| 이름 | 값 | 의미 |
|---|---|---|
| 프런트엔드 소스 | `nextjs/` | 개발·실행·CI 작업 폴더. 변경 완료 |
| 기본 테마 소스 | `nextjs/themes/default/` | 후속 구현에서 도입할 디자인·설정 분리 위치 |
| 배포 테마 | `nextjs_default` | Django가 선택하고 서빙할 테마 식별자 |
| Django 템플릿 | `gnu_jango/templates/theme/nextjs_default/` | 사용자가 지정한 목표 경로의 저장소 내 실제 위치 |
| Django 정적 자산 | `gnu_jango/templates/theme_static/nextjs_default/` | 빌드된 JS·CSS·별도 자산 |
| 표시 이름·로고 | 사이트 설정에서 관리 | 참고 소스의 Solune 표기를 설치 사이트의 브랜드로 변경 가능 |

소스 폴더명과 Django 테마 산출물 경로 전환을 완료하고 커뮤니티·쇼핑 기능과 관리자 테마 설정을 연결했다. 독립 Next.js 생산 서버의 공개·인증 경로, 빌드 후 게시글 렌더링, 소유권·누락 자원 API 회귀를 확인했다. 2026-10-08에는 프로젝트·SQLite·미디어 복제본을 별도 로컬 서버에서 실행해 패키지 설치·전환·복구와 데이터 보존도 확인했다. 기반 실행·연동 수용은 완료했으나 쇼핑몰·게시판 서브페이지 디자인 수용은 남아 있다. 외부 서비스 배포와 P1 확장은 별도 작업이다.

## 2. 배경과 참고 기준

대상 프로젝트는 이미 Django/DRF API, 게시판·회원·쇼핑 기능, Next.js 앱, 정적 테마 서빙 기능을 갖고 있다. 기존 테마와 자산은 `nextjs25` 경로를 사용한다. 참고 PHP 프로젝트의 최근 기본 테마는 `nextjs/themes/default`에서 디자인을 분리하고 `theme/nextjs_default`에 배포한다.

따라서 기존 Django 데이터·권한 처리에 참고 테마를 연결하는 방식으로 개발한다. PHP 코드나 완성된 HTML만 복사해서 화면을 맞추는 방식은 API·주소·인증·동적 데이터 요구사항을 충족하지 못한다.

| 참고 | 제품 기준으로 사용할 내용 |
|---|---|
| `C:\xampp824\www\gnuboard5_3\nextjs\themes\default` | 커뮤니티·쇼핑 레이아웃, 테마 슬롯, 디자인 토큰, 위젯, 반응형 동작 |
| `C:\xampp824\www\gnuboard5_3\theme\nextjs_default` | 사용자 주소·PWA·정적 산출물·런타임 브리지의 기능 계약 |
| [http://127.0.0.9/](http://127.0.0.9/) | 개발 환경에서의 기본 사용자 흐름 |
| [Cafe24 참고 사이트](https://thisgun3.mycafe24.com/) | 호스팅 환경에서의 화면·주소·자산 동작 |
| [Vercel 데모](https://gnuboard5-nextjs-demo.vercel.app/) | 독립 Next.js 실행과 API 연결, 메타데이터·공유 링크 |

2026-10-07에 세 사이트의 홈 HTTP 200과 공개 메뉴를 확인했다. 소스의 기본 테마 표시명은 Solune이며 Vercel에서도 이 표기가 보인다. 사이트별 메뉴·콘텐츠·설정은 다를 수 있다. 실제 배포 커밋, 인증·주문 동작, 브라우저 시각 비교는 아직 확인하지 않았으며 구현 전 기준 조사에서 기록한다.

## 5. 화면과 동작 요구사항

### 5.1 공통 화면과 커뮤니티 홈

- 커뮤니티와 쇼핑몰을 오갈 수 있는 서비스 전환, 로고·검색·회원 메뉴, 푸터를 제공한다.
- 참고 기본 테마의 고정 헤더·축소 동작·모바일 드로어와 게시판 패널·사이드바 구성을 이식한다.
- 홈에는 게시판별 최신글, 새글·인기글, 갤러리와 제공 가능한 회원·설문·검색·접속자 위젯을 배치한다.
- 글·상품·위젯 내용은 Django API의 데이터를 사용한다. 공개된 실제 글이 없으면 설명이 있는 빈 상태를 표시한다.
- 사이트 제목·로고·고객센터·메뉴는 설정을 사용하고 참고 사이트의 이름·개인 연락처를 배포 기본값으로 복사하지 않는다.

### 5.2 게시판과 회원 공간

- 게시판 목록·검색·페이지 이동·글 상세·댓글·작성/수정·첨부파일은 현재 Django 권한과 API에 따른다.
- 비밀글·작성자 전용 수정·삭제·회원 전용 게시판은 서버에서 권한을 검사한다.
- 입력 오류는 항목 가까이에 표시하고, 업로드 중·저장 중·성공·실패 상태를 구분한다.
- 회원 공간의 개인 데이터는 인증 후 조회하고 인증 만료 시 재로그인 흐름을 제공한다.

### 5.3 쇼핑몰

- 상점용 레이아웃, 배너·분류·상품 진열·상세 탭·구매 옵션을 참고 기본 테마에 맞춰 제공한다.
- 상품 가격·재고·옵션·배송비·할인·주문 합계는 Django API를 기준으로 한다.
- 장바구니 수정·삭제, 주문서 입력, 주문 결과·내역의 API 오류와 품절 상태를 처리한다.
- 결제 실행은 기존 지원 범위 안에서 설정된 테스트 PG로 검증한다. 실결제 성공을 테마 개발의 검증 기준으로 삼지 않는다.
- 미설정 PG나 미지원 결제수단을 선택 가능한 정상 기능으로 표시하지 않는다.

### 5.4 테마 설정과 운영자

- 운영 관리자 주소는 Django `/admin/`이며 사용자 테마에서 해당 관리자에 연결한다.
- 현재 앱에 있는 Next.js 관리자 화면과 `/admin` 경로의 처리 정책을 설계에서 정리해 Django 관리자 접근을 방해하지 않게 한다.
- 기본 테마 표시명·색·로고·위젯 사용 여부는 공통 API·회원·주문 코드를 수정하지 않고 바꿀 수 있게 분리한다.

## 6. 기술·통합 요구사항

### 6.1 API와 인증

Django `/api/v1`이 이 테마의 백엔드다. 참고 PHP 사이트의 API 응답은 호환성 조사 기준이며 새 테마의 고정 API 주소가 아니다. 필요한 응답 차이는 Django API 또는 프런트의 타입·어댑터 계층에서 해결한다.

독립 Next.js 서버는 `G5_NEXT_RUNTIME=server`와 서버 전용 `G5_API_INTERNAL_URL`을 사용한다. 브라우저 요청은 가능한 한 `/api/v1` 프록시로 처리한다. Django 정적 테마는 요청의 사이트·경로에 맞춘 런타임 설정으로 API를 연결한다.

회원 인증은 기존 JWT·refresh cookie 계약을 따르고, Django 관리자 세션은 해당 관리자 흐름을 유지한다. 민감한 키와 서버 전용 API 주소를 공개 번들에 넣지 않는다. 로그인 복귀 URL은 내부 주소만 허용한다.

### 6.2 빌드와 런타임

- `nextjs/out`의 HTML·공개 파일과 `_next`·`assets`를 목표 두 디렉터리에 분리한다.
- sync와 check 스크립트, Django 렌더러·정적 자산 경로, 기본 테마 설정을 같은 변경에서 맞춘다.
- 정적 빌드 이후 추가된 게시글·상품의 직접 진입과 RSC 이동을 지원한다.
- 기존 런타임 설정 키·결제 콜백 이름은 새 이름과의 호환성을 확보한 뒤 변경한다.
- 정적 테마를 실행할 때 Node 개발 서버에 의존하지 않는다. 독립 서버 배포는 별도 실행 모드로 관리한다.

### 6.3 백엔드와 데이터

현재 Django 모델과 사용자 데이터를 재사용한다. 참고 PHP 테마를 적용하기 위해 DB를 재설치하거나 개발 데이터를 덮어쓰지 않는다. 신규 API·모델이 필요하면 요구사항과 마이그레이션을 별도로 정의한다.

AC-14의 대상 환경은 원본 프로젝트와 DB가 분리된 로컬 환경으로도 구성할 수 있다. 이 항목은 설치·전환·복구의 재현 기준이며, 제품 범위에서 제외한 외부 호스트 배포를 필수 조건으로 추가하지 않는다. 완료 증거와 남은 운영 범위는 [갭 분석](../../03-analysis/nextjs-default-theme.analysis.md) 및 [배포 가이드](../../04-deploy/nextjs-default-theme.md)에 기록한다.

- Django 정적 테마와 독립 Next 홈의 콘텐츠 E2E가 통과했고, 정적 테마 빌드·동기화 350개 파일, Django 검사, 마이그레이션 검사, TypeScript 및 설정 lint가 통과했다.

## 2026-10-07 인증 주문 화면 검증 추가

- 로컬 임시 회원으로 로그인하고 상품 1개를 카트에 담은 뒤 주문/결제 화면을 확인했다. 카트 생성 API HTTP 201, 주문 화면의 상품·주문자·받는 분·결제·쿠폰/포인트·약관·금액 영역, 런타임 오류 0건을 확인했다.
- 390/768/1280/1440px 모든 폭에서 가로 넘침이 없었다. 테스트 회원과 카트 데이터는 확인 즉시 삭제했고, 주문제출과 결제는 실행하지 않았다.
- 임시 회원은 저장 배송지·보유 쿠폰이 없어 주소 입력 폼과 빈 쿠폰/포인트 상태만 확인했다. 보유 항목의 선택 흐름은 별도 테스트 데이터가 필요하다.

## 2026-10-07 공개·인증 경로 검증 업데이트

- 공개 브라우저 검사 25개와 인증 회원·관리자 경로 16개가 통과했다. 인증 경로에는 회원 홈·주문·위시리스트, 관리자 대시보드·회원·게시판·설정·상품·주문·문의가 포함된다.
- 인증 검사는 공유 DB 잠금을 피하려고 로컬 SQLite 복제본에서 실행했다. 임시 사용자 2명, 주문, 문의를 정리하고 DB 조회로 잔여 레코드가 없는 것을 확인했다.
- smoke 로그인 컨텍스트가 앱 클라이언트의 메모리 토큰을 올바르게 초기화하도록 보완했다. 설정 화면의 Select 레이블 연결과 관리자 상품 이미지 실패 시 플레이스홀더도 추가했다.
- 교차 회원 소유권과 누락 자원 오류 행렬, 최신 코드 정적 빌드·테마 동기화, 스테이징 전환·복구 검증은 남아 있다. 운영 호스트 변경과 외부 결제는 실행하지 않았다.

## 2026-10-07 회원 데이터 소유권 검증 업데이트

- 메모리 테스트 DB 회귀 묶음 64개에서 58개 통과, SPA 이전에 따른 레거시 뷰 테스트 6개 건너뜀, Django 시스템 검사 오류 0건을 확인했다.
- 장바구니·위시리스트·배송지·주문·쿠폰·리뷰·문의 목록의 회원별 범위, 타 회원 상세 접근과 변경 차단, 비밀 문의의 개인정보 마스킹, 배송지·주문·리뷰·문의 누락 ID의 404를 검증했다.
- 새 콘텐츠의 브라우저 렌더링, 독립 Next.js 서버 응답, 지정 스테이징에서의 전환·복구는 아직 검증하지 않았다. 해당 확인 전까지 PRD 완료 상태로 전환하지 않는다.

## 2026-10-07 신규 콘텐츠 동적 fallback 확인

- 빌드 뒤 생성한 메모리 테스트 DB의 게시글·상품에 대해 짧은 주소와 canonical 주소가 Django 정적 테마 fallback에서 HTTP 200을 반환하고, 상세 API가 생성 직후의 콘텐츠를 돌려주는 회귀 테스트를 추가했다.
- 신규 레코드 fallback 회귀 테스트 2개와 Django 시스템 검사가 통과했다.
- 관련 권한·사용자·관리자·fallback 테스트 통합 실행은 66개 중 60개 통과, SPA 이전에 따른 레거시 화면 테스트 6개 건너뜀이다.
- Django 모드의 신규 레코드 API 연결은 확인했다. 브라우저에서 새 레코드가 완전히 렌더링되는지와 독립 Next.js 서버의 새 레코드 응답은 아직 확인하지 않았다.

## 2026-10-08 독립 Next.js 서버와 신규 게시글 확인

- 원본 SQLite DB의 일관된 복제본과 임시 Django API를 사용해 Next.js 생산 서버 빌드를 수행했다. Next.js 15.5.18이 1,074개 경로를 생성했고 API 연결 거부 없이 완료됐다.
- 빌드가 끝난 뒤 복제 DB의 `free` 게시판에 새 게시글을 만들었다. 해당 경로가 prerender manifest에 없음을 확인하고, 독립 Next 서버에서 직접 연 결과 HTTP 200과 게시글 제목·본문 렌더링을 확인했다.
- 생산 서버에서 익명 경로 25개를 데스크톱과 모바일(390×844)로 각각 통과했다. 별도의 인증 실행에서는 회원·관리자·주문·문의 화면을 포함한 41개 경로가 통과했다. 첫 인증 준비 실행의 FAQ에서 hydration 오류가 한 차례 발생했지만, FAQ 단독 실행과 전체 재실행은 통과했다.
- Django 정적 테마의 `check-local-runtime`도 통과했다. 개인 경로 noindex/no-store, API 연결, 메타데이터, PWA 자산, RSS·리다이렉트와 10개 `.txt` RSC 응답의 content type 및 보안 헤더를 확인했다.
- 임시 게시글·계정·주문·문의는 SQLite 복제본에만 생성했으며 원본 DB와 결제 처리에는 접근하지 않았다. 전체 교차 회원 소유권·누락 자원 행렬 및 지정 스테이징 전환·복구 검증은 남아 있다.
- 게시판·댓글·스크랩·장바구니·위시리스트·배송지·주문·쿠폰·리뷰·상품 문의·개인결제 API의 권한과 누락 ID를 포함한 Django 회귀 테스트 41개를 실행했다. 35개 통과, 레거시 상세 화면이 SPA로 이동한 6개 테스트는 건너뛰었고 시스템 검사에 오류가 없었다.
