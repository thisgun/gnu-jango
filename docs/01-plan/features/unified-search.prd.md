# PRD: 게시판·상품·문서 통합 검색

작성일: 2026-10-21

## 후속 수용 기준 (2026-10-21)

- 자유로운 질문이 공개 인기어 목록으로 바로 노출되지 않는다. 명시적으로 허용한 단어와 최소 집계 기준을 모두 만족해야 한다.
- 실패·차단된 검색, DNT 요청, 민감 표현으로 보이는 검색은 방문·검색 집계에 기록하지 않는다.
- 범위를 넘긴 페이지 요청은 유효한 페이지 번호와 결과를 반환한다. 원문 조회는 현재 페이지의 결과로 제한한다.
- 재색인은 기존 활성 색인을 유지하고 완료 후 새 세대로 전환한다. 원본 자료와 클릭 FK는 보존한다.
- 예약 실행기가 오래된 클릭을 정리하고 dry-run은 삭제하지 않는다.
- Preview는 DEBUG=False이며 전용 역할·스키마를 확인하지 못하면 DB 연결을 거부한다. 운영 테이블 접근과 외부 결제·메일 발송을 허용하지 않는다.

## 사용자 문제

방문자는 같은 검색어를 게시판과 쇼핑몰에서 각각 입력해야 한다. 한국어 질문에 조사가 붙거나 단어 순서가 달라지면 결과가 줄어든다. 운영자는 자료가 많아진 뒤에도 외부 유료 검색 서비스를 필수로 도입하지 않고 검색을 운영할 수 있어야 한다.

## 사용자 경험

- 사이트 검색에서 게시글·상품·문서를 함께 보고 종류로 좁힌다.
- 제목이 맞는 자료와 질문 단어를 더 많이 포함하는 자료가 먼저 나온다.
- 본문은 읽을 수 있는 범위의 짧은 일반 텍스트만 표시한다.
- 상품의 가격·이동 링크와 문서의 제목·이동 링크를 제공한다.
- 작성자/특정 게시판 검색 및 기존 게시판별 더 보기 동작은 유지한다.
- 검색 준비가 끝나지 않았거나 요청이 실패하면 명확한 안내와 기존 게시판 검색을 제공한다.

## 기능 요구사항

| ID | 요구사항 | 수락 조건 |
|---|---|---|
| S1 | 공통 한국어 토큰화 | 기존 Kiwi/2-gram 모듈 재사용, 분석기 버전 불일치 감지 |
| S2 | DB 색인 | PostgreSQL GIN FTS, SQLite 토큰 역색인, pg_trgm 선택 활성화 |
| S3 | 통합 API | `/api/v1/search/unified?q=...&type=all|post|product|document&limit=20&page=1` |
| S4 | 권한 | 기존 `_searchable_boards`, `readable_post_queryset`, 포인트 열람 규칙에 부합; 비밀 본문은 색인 검색/스니펫/점수에 사용하지 않음 |
| S5 | 랭킹 | 제한된 후보의 BM25, 제목 가중치, 인기어/클릭 보정은 관련 문서에만 적용 |
| S6 | 클릭 | `/api/v1/search/click` POST, 15분 유효 서명 토큰, 일별 집계, 중복·봇·DNT 제한 |
| S7 | 색인 관리 | `rebuild_search_index`, 선택 `--kind`, 원문 저장/삭제 자동 반영, 클릭 보관기간 정리 명령 |
| S8 | 기존 API | 준비된 색인 사용, 준비되지 않은 상태·작성자 필드 검색은 기존 동작; 명시 상품 정렬 유지 |
| S9 | 화면 | 기본 사이트 검색에 통합 결과 표시, 특정 게시판/작성자 검색은 기존 화면 유지 |

## 운영 및 비기능 요구사항

- 새로운 검색 서비스 계정, Redis, Celery worker를 필수로 요구하지 않는다.
- Kiwi 설치는 선택 사항이다. 기존 `requirements-docs-morphology.txt`를 사용한다.
- 검색어는 2~200자, query token은 최대 24개, 문서 본문 토큰은 최대 4096개, BM25 후보는 최대 200개로 제한한다.
- 본문 토큰 상한을 넘는 긴 글은 앞부분만 색인된다는 한계를 운영 문서에 명시한다.
- 모든 권한 필터는 요청마다 원본 모델을 기준으로 적용한다. 사용자별 결과를 공용 캐시에 저장하지 않는다.
- 클릭 저장에는 사용자 ID·IP 원문·전체 질문을 보관하지 않는다. 일별 query hash와 문서 ID·횟수만 저장한다. 중복 제한용 캐시 키도 HMAC으로 익명화한다.
- 조회 요청은 새 색인을 생성하거나 원문 전체를 메모리로 읽지 않는다.
- 테스트 데이터에서 한국어 질문 15개 이상 평가하고 정답이 상위 3개에 드는 비율 80% 이상을 목표로 한다. 대규모 운영 p95 지연시간 목표는 실제 PostgreSQL 데이터로 별도 측정한다.

## 이번 범위 밖
