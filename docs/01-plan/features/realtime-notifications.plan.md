# 실시간 회원 알림 구현 계획

## 목표

댓글·쪽지·주문 변경·관리자 공지를 기존 회원 알림함에 저장하고 Channels + Redis로 즉시 갱신한다.
WSGI 배포에서도 알림함을 사용할 수 있도록 REST 조회를 유지한다.

## 순서와 구현 위치

1. 기존 `Notification`을 사용한다. 댓글/수신 쪽지 생성, 주문 상태 변경을 공통 모델 신호에 연결한다.
2. `notifications/ticket`에서 로그인과 CSRF를 검사하고 30초 일회용 접속권을 발급한다.
3. `example.asgi`에 Origin 제한과 개인별 Channels 그룹을 연결한다.
4. 원본 커밋 이후 알림을 생성하고 실패는 DB 대기열에서 재시도한다. Redis 변경 신호는 전용 작업자가 전달한다. 알림 본문은 REST 권한 검사 이후 조회한다.
5. 알림 벨에 재연결·백오프·탭 전환·폴링 복구를 추가한다. 두 Django 테마를 함께 빌드한다.
6. 관리자 공지 발송 화면과 조회용 DB 인덱스를 추가한다.
7. 선택 설치 requirements, Docker ASGI 설정, 배포/장애 대응 가이드를 남긴다.

## 범위와 배포

- 현재 저장소에 Expo/React Native 앱은 없다. FCM/APNs 토큰 등록과 외부 푸시 전송은 이번 범위에 포함하지 않는다.
- Channels는 선택 설치한다. `NOTIFICATION_WS_ENABLED=False`가 기본이며 기본 설치 용량을 늘리지 않는다.
- Preview는 WebSocket을 끈다. 실제 전송을 켜려면 ASGI·전용 Redis 설정·정확한 Origin 설정이 필요하다.
- 이 변경의 `core.0013`~`0014` 마이그레이션은 운영에 미적용 상태로 제공한다. 이전 검색 작업의 마이그레이션도 별도로 배포 준비해야 한다.
- 운영 DB, 기존 개발 서버, Vercel 프로젝트에는 자동으로 적용하지 않는다.

## 완료와 확인 범위

- Python 코드 정적 검사, Django 시스템 점검, 모델/마이그레이션 차이 확인.
- Next.js 타입 점검과 기본/핸드북 테마 빌드 및 빌드 자산 일치 확인.
- 2026-10-22 후속 요청에 따라 격리한 실제 Redis·HTTP/WebSocket 연결, PostgreSQL 동시 처리와 브라우저 복구 테스트를 추가해 실행한다.
