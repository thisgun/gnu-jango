> **Level**: 기존 Django/DRF + Next.js 앱 개선

## 1. 목표와 배경

홈 화면을 맞춘 뒤 쇼핑몰과 게시판까지 같은 수준으로 이식되지 않아 페이지 이동 시 디자인과 정보 배치가 달라진다. 기존 `nextjs-default-theme`의 실행·인증·빌드·설치·복구 기록은 유지하되, 서브페이지의 시각적 일치를 별도 수용 기준으로 관리한다. 이전의 홈 QA와 경로 접근 성공을 이번 네 화면의 디자인 완료 근거로 사용하지 않는다.

이번 목표는 새로운 디자인을 만드는 것이 아니라 사용자가 지정한 `127.0.0.9`의 화면 구조, 정보 순서, 간격, 이미지 영역, 주요 조작 방식을 Django 데이터와 권한에 맞게 이식하는 것이다.

### 화면 외에 먼저 해결할 문제

1. **배너 API와 슬라이더**는 초기 조사 때 비어 있었으나 저장/API/관리와 배너 캐러셀을 추가했다. 이번 단계에서는 배너가 없는 상태, 관리 화면 전체 수용과 배포 media 접근을 더 확인한다.
2. **상품 이미지와 빈 상태**는 앱 아이콘 대체를 제거하고 실제 상품 사진·상품 폴더 대체 이미지·빈 이미지 안내를 구분하도록 수정했다. 원격 정적 호스트에서의 이미지 접근은 남아 있다.
3. **옵션과 상품 메타데이터**를 보존하는 계약을 추가하고 `1446772772`의 SIZE/COLOR 선택지를 복구했다. 복제 DB에서 선택/금액 계산/카트 전달을 확인했으며 품절·오류 경계는 남아 있다.
4. **페이지별 shell**은 상점 헤더와 커뮤니티 레일을 분리했다. 상점 헤더에 원본 로고와 상품 유형 메뉴를 배치하고 390/768/1440px의 구조·색상·아이콘 위치를 기준과 맞췄다. 게시판 fixture와 상품 행/오류 상태의 시각 수용은 진행 중이다.

상품명·게시글 내용·레코드 수·가격·후기 수·옵션 유무는 서로 다른 데이터의 차이일 수 있다. 비교를 위해 기존 데이터를 덮어쓰지 않는다. 디자인 평가용으로는 복제 환경에 같은 조건의 글·상품을 준비한다.

## 3. 범위

### P0: 이번 개선의 완료 범위

아래 체크 항목은 코드 반영뿐 아니라 연결된 화면/동작 확인까지 마쳤을 때 체크한다. 현재는 여러 화면의 1차 구현이 들어갔으며, 어느 화면도 수용 완료로 처리하지 않았다.

- [ ] 네 화면과 데스크톱·태블릿·모바일의 기준 상태 정의
- [ ] 커뮤니티 서브페이지 shell과 오른쪽 회원/최근 댓글/인기 검색어 레일
- [ ] 쇼핑몰 전용 서비스 바·헤더·카테고리 메뉴·푸터·색상 토큰
- [ ] 배너 관리/API, 분류 표시, 상품 이미지와 옵션명 데이터 계약
- [ ] 쇼핑몰 홈의 배너·분류·상품 행·후기·공지/고객센터 구성
- [ ] 상품 상세의 갤러리·구매 패널·옵션·탭·데스크톱 구매 보조 패널
- [ ] 게시판 목록의 제목·분류·표/모바일 행·쪽 이동·검색
- [ ] 글 상세의 머리·본문·첨부·반응·댓글·이전/다음·목록 이동
- [ ] 긴 제목·이미지 없음·빈 결과·오류·비회원/회원/관리자 상태
- [ ] 정적 테마 반영과 네 화면별 비교 기록

### P1: 네 화면 완료 후 확장

분류/상품 검색 페이지 → 장바구니/주문서 → 후기/문의 목록 → 글쓰기/갤러리/회원 페이지 순서로 같은 shell과 컴포넌트를 확장한다. 이 페이지들은 이번 네 화면에서 연결되는 경로의 기본 동작과 공통 shell 회귀 확인 대상이며, 별도 화면 비교 없이 디자인 완료로 표시하지 않는다.

### 제외 범위

PHP 원본 수정, 기존 업무 데이터 전체 이관/정리, 실제 결제, 운영 배포, 새로운 브랜드 디자인, 관리자 전체 재개발. 관리자 변경은 배너·분류 표시·상품 이미지/옵션 이름 등 이번 화면 운영에 필요한 최소 설정에 한정한다.

### 중요한 구현 결정

- 루트의 Header/Footer와 shop layout이 중복으로 그려지지 않도록 shell 책임을 먼저 정한다. `<main>`과 `#main-content`도 페이지당 하나만 둔다.
- 커뮤니티의 파란 토큰과 상점의 흰 바탕·짙은 녹색·할인 강조색을 영역별로 분리한다. 모달 portal에도 해당 영역 토큰을 적용한다.
- DaisyUI의 drawer/menu, card, table, tabs, button, input/select를 기본으로 사용한다. 기준과 다른 기본 여백·모서리는 해당 영역에서 조정한다.
- 배너 자동 재생·정지·진행 표시와 상품 행 이동은 명시적인 상태와 조작을 구현한다. DaisyUI carousel 클래스만 붙여 해당 기능이 완성됐다고 간주하지 않는다. 기준 Swiper 이식과 현재 스크롤 방식의 보완은 S0에서 동작·의존성을 비교해 선택한다.
- 구매 패널은 화면 위·보조 패널·모바일 진입에서 같은 옵션/수량 상태를 공유한다. 계산 로직을 복제하지 않는다.
- 배너 수정과 새 상품은 정적 빌드에 없는 데이터도 런타임 API로 반영되게 한다. 생성 산출물만 수동 수정하지 않는다.

## 6. 단계별 확인 기준

| 구분 | 필요한 확인 | 완료 증거 |
|---|---|---|
| 시각적 일치 | 1440×900, 768×1024, 390×844에서 같은 상태로 상단·중간·하단 비교 | 화면/폭/상태별 캡처와 DOM 치수, PRD AC-V 기록 |
| 사용자 동작 | 배너·분류·목록 검색/쪽 이동·댓글·갤러리·옵션·카트/구매 진입 | PRD AC-F 확인표와 실패/제한 기록 |
| 데이터 | 정상 이미지·없음·실패, 실제 옵션명, 배너 게시 기간/기기 조건 | fixture와 API 표시 대응표 |
| 기존 기능 보존 | 가격·옵션 추가금·재고·권한·짧은 주소·로그인 복귀 | 영향 있는 기존 계약의 확인 결과 |
| 반영 | 소스 → 정적 빌드 → 두 Django 테마 폴더 → 실제 8081 화면 | 변경 빌드 식별/동기화 기록과 실제 화면 캡처 |

S1~S5의 1차 구현과 수용 확인을 진행했다. 격리 DB에서 Django check 및 makemigrations 확인, 복제 환경의 주요 동작, 1,074개 경로의 정적 빌드와 2,320개 파일 동기화를 확인했다. 390/768/1440px 캡처에서 가로 넘침이 없고, 홈 분류 카드와 히트상품 위치 및 상품 상세 주요 기준점이 기준에 맞거나 1px 이내다. 남은 시각·fixture·원본 8081 쓰기 동작을 별도 확인하기 전에는 완료 처리하지 않는다. 신규 자동 테스트나 전체 테스트 실행은 별도 요청이 있을 때 추가한다.

### 완료 정의

- [ ] PRD의 P0 요구사항마다 구현 파일과 확인 증거가 연결됨
- [ ] 네 화면 각각 AC-V와 AC-F를 충족하고 미확인 상태가 없음
- [ ] 데이터가 다른 부분은 예외 사유가 있고 같은 조건 fixture에서도 구조가 맞음
- [ ] 고정 메뉴/구매 버튼이 본문·댓글 입력·팝업을 가리지 않음
- [ ] 상점/커뮤니티 전환 후 토큰과 헤더가 정상 복원됨
- [ ] 실제 Django `nextjs_default` 화면에 최신 산출물이 반영됨
- [ ] 문서·변경 이력·알려진 제한이 갱신됨

전체를 하나의 일치율로 닫지 않는다. 예를 들어 쇼핑몰 홈 완료/상품 상세 진행/게시판 목록 대기처럼 화면별로 표시한다.

## 7. 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 서로 다른 글/상품을 그대로 픽셀 비교 | 데이터 차이를 버그 또는 완료로 잘못 판정 | 원본 URL 비교와 별도로 데이터 조건을 맞춘 fixture 사용 |
| 전역 CSS로 상점 디자인 적용 | 홈/회원/관리자 또는 portal 모달에 색상 누출 | 영역별 토큰, shell 전환과 portal 확인 |
| 화면 이식 과정에서 기존 구매 로직 교체 | 재고·할인·수량 규칙 퇴행 | `useProductOptions`와 서버 계산 유지, 표시 계층 중심 개선 |
| 배너/옵션명 저장 구조 부재 | 프런트만 수정해도 화면 미완성 | S1에서 저장·관리·API·타입까지 정의, 추가 migration은 기존 데이터 보존 |
| 사진 대신 앱 아이콘으로 빈 상태 은폐 | 상점 신뢰도 저하 | 이미지 용도/원본 출처 확인, 실제 없음/실패 상태로 표시 |
| 정적 빌드 당시 데이터만 노출 | 배너 수정·새 레코드가 보이지 않음 | 런타임 갱신과 직접 진입을 수용 조건에 포함 |
| 긴 글·제목·옵션/고정 버튼 | 모바일 읽기와 구매 조작 방해 | 긴 문자열 fixture, 줄바꿈, 하단 여백과 고정 UI 겹침 확인 |
