# 검색 신뢰성 보강 PRD

## 사용자와 문제

- 방문자: 부분 상품코드나 짧은 단어로 기존 자료를 찾는다.
- 글 작성자: 글 저장 후 색인 실패로 자료가 영구 누락되지 않아야 한다.
- 운영자: 보호된 본문의 검색 추론을 막고 색인 누락·지연을 감지·복구한다.

## 요구사항

| ID | 동작 | 수용 기준 |
|---|---|---|
| R1 | 공통 본문 열람 필터 | 비회원/미결제/낮은 등급의 혼합·대체 검색에 보호 본문이 영향 없음 |
| R2 | 부분 검색 호환 | 기존 API의 한 글자·ASCII 부분 문자열 유지, 통합 API의 2자 이상 ASCII 접두 지원 |
| R3 | 저장·색인 일관성 | 원본과 성공 색인 또는 재시도 식별자가 같은 트랜잭션에 존재, 실패 재처리는 유한 묶음/백오프 |
| R4 | 누락 점검 | 종류별 원본 지문·활성 세대를 검사, 커서로 이어 읽기, 명시적 옵션으로만 복구 예약 |
| R5 | 규모 검증 | 일회용 로컬 PostgreSQL 1만 건·100문항·동시 읽기/쓰기 검사와 측정 결과 |
| R6 | 운영 감시 | 준비 상태·미처리 작업·세대 불일치·원본 순환 검사·지연의 비정상 종료 코드 |
| R7 | 배포 검사 | 성공한 main CI 이후 두 공개 사이트의 커밋을 확인한 뒤 익명 정답표 실행, 실패 시 Actions 실패 및 결과 보관 |

## 검색 의미와 범위

통합 검색의 한국어 형태소/2-gram 규칙, 후보 200건 제한, BM25 제목 가중치는 유지한다. ASCII 접두는 색인 조회와 BM25에 같은 규칙을 적용한다. 기존 API의 ASCII 부분 문자열은 권한을 적용한 리터럴 검색으로 처리하므로 넓은 조건에서는 원문 조회 비용이 발생할 수 있다. 통합 API의 2자 최소 길이는 유지한다.

## 비기능 요구

- 무료 배포 환경에서 별도 워커 없이 예약 명령으로 복구한다.
- 로그와 검사 결과에는 검색어·본문·인증 정보·예외 원문을 포함하지 않는다.
- 합성 정답표 성공률과 소규모 운영 정답표 성공률을 구분한다.
- 콜드 스타트와 실제 고객 동시 접속 처리량은 별도 계측 전까지 보장하지 않는다.
- 모든 신규 쓰기 테이블은 배포 전에 마이그레이션하고 기존 코드와의 순서를 문서화한다.
