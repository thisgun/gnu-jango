# 검색 권한·호환성·복구·규모 검증 계획

작성일: 2026-10-21

## 목표

1. 혼합 필드와 색인 대체 검색에도 본문 권한을 일관되게 적용한다.
2. 기존 부분 검색을 유지하고 통합 검색에 ASCII 접두 일치를 제공한다.
3. 원본 저장과 색인/재시도 기록을 함께 커밋하고 실패를 복구한다.
4. 격리 PostgreSQL 1만 건으로 후보 제한·동시 조회·수정을 검증한다.
5. 예약 작업의 상태 점검과 배포 커밋에 맞는 공개 정답표 검사를 자동화한다.

## 순서

- 권한 공통 필터와 혼합 필드·비밀/유료/읽기 등급 회귀 검사.
- 기존 API의 한 글자/ASCII 부분 검색 및 통합 검색의 접두 검색.
- 트랜잭션 경계, 재시도 테이블, 지수 백오프와 검사/복구 명령.
- 1만 건 합성 정답표 100문항, 동시 검색과 저장, 병목 개선.
- SQLite/PostgreSQL 회귀, 전체 프로젝트 검사, 변경·한계 보고.

## 제약

운영 DB, Supabase, 8081 서버, 사용자 작업 파일은 변경하지 않는다. 신규 대량 자료는 이름과 접속 대상을 제한한 로컬 일회용 DB에만 만든다. 검색어·본문·IP·예외 원문을 새로운 진단 로그에 기록하지 않는다. Celery, Redis, 외부 검색 서비스는 추가하지 않는다. 이번 작업은 로컬 구현이며 커밋·푸시·배포는 별도 요청 시 진행한다.

## 완료 기준

- 열람 권한이 없는 요청에서 보호 본문 표식이 혼합/대체 검색 결과·건수에 영향을 주지 않는다. 기존 작성자·잠금 해제 세션의 리터럴 검색 권한은 보존한다.
- 한글 한 글자와 ASCII 부분 코드의 기존 검색 결과가 유지된다.
- 색인 오류·원본 롤백·재시도 오류·대량 수정 후 복구가 검증된다.
- 두 DB 회귀 결과와 합성 데이터의 품질·지연·표본 한계를 보고한다.
- 배포 가이드에 신규 마이그레이션 순서와 복구·예약 작업 운용법을 적는다.
