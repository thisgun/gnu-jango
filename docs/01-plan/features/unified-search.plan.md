# 통합 검색 고도화 계획

작성일: 2026-10-21 · 상태: 구현·격리 환경 검증 완료 · 운영 DB 반영 전

## 목적과 조사 결과

`api/search.py`의 부분 문자열 OR 검색과 게시판별 순회 검색은 한국어 조사·띄어쓰기 변형에 약하고, 자료가 늘면 원문을 반복해서 읽는다. `docs_search`에는 이미 Kiwi/한글 2-gram 토큰화와 BM25가 있다. 이를 게시글·상품·내용관리 문서까지 확장한다.

## 범위와 구현 순서

1. 공통 검색 문서와 토큰 역색인, 준비 상태 및 클릭 일별 집계 모델을 추가한다.
2. 저장·삭제 시 같은 DB 트랜잭션으로 색인을 갱신하고, 기존 자료는 재색인 명령으로 처리한다.
3. PostgreSQL에서는 `SearchVector(config='simple')`와 동일 표현식의 GIN 인덱스로 후보를 검색한다. SQLite에서는 토큰 B-tree 역색인을 사용한다. pg_trgm 오타 검색은 PostgreSQL에서 선택적으로 설치·활성화한다.
4. 기존 게시판·상품 API의 응답 형태와 명시적 정렬은 유지하면서 색인이 준비된 경우 토큰 검색을 사용한다. 작성자 검색 등 호환 필드는 기존 검색을 유지한다.
5. 게시글·상품·매뉴얼/내용관리 문서를 하나의 API에서 관련도 순으로 제공하고 검색 화면에 연결한다.
6. 검색 결과 클릭은 서명된 결과 토큰으로 수집하고 중복·봇 요청을 제한한다. 인기 검색어와 클릭 집계는 제한된 보정만 허용한다.
7. 권한·검색 품질·색인 수명주기·기존 API 회귀 테스트를 수행한다. 두 Django 테마 산출물도 함께 갱신한다.

## 완료 기준

- 한국어 토큰화가 게시판·상품·문서에 동일하게 적용된다. Kiwi가 없어도 추가 패키지 없이 동작한다.
- 비밀글, 검색 제외 게시판, 열람 레벨, 읽기 포인트, 판매 중지·비활성 카테고리, 비공개 문서가 검색 결과·점수·클릭 API를 통해 노출되지 않는다.
- 후보 검색은 DB 색인을 이용하며, Python BM25 계산은 최대 200개 문서로 제한한다. 후보 제한과 실제 엔진을 응답에 표시한다.
- 색인 미준비 상태에서는 기존 검색 API가 작동한다. 새로운 통합 API는 재색인이 필요함을 명확히 알린다.
- 기존 자료 재색인, 대량 import 후 재색인, 형태소 분석기 변경 후 재색인 및 되돌리기 절차를 문서화한다.
- 실제 운영 데이터/배포 환경 변경은 별도 반영 시 수행한다. 이번 작업에서는 코드·마이그레이션·테마·검증 결과를 준비한다.

## 위험과 대응

| 위험 | 대응 |
|---|---|
| private 본문이 점수나 검색 건수로 유출 | 후보 선택부터 권한 검사, 점수 계산에서도 읽을 수 없는 본문 제외 |
| 서버리스 메모리/디스크 제약 | 영속 DB 색인, 후보·토큰 상한, 파일 색인/상주 프로세스 없음 |
| bulk_create/update가 signal을 생략 | 명시적 재색인 명령과 배포 절차 제공 |
| 클릭 조작·인기어 편향 | 만료 서명, 현재 권한 재검사, 익명화된 중복 제한, 최대 보정 비율 |
| PostgreSQL 확장 권한 부족 | 기본 FTS는 확장 불필요, pg_trgm은 선택 명령으로 설치 |
| Kiwi 설치/제거 후 토큰 체계 변경 | 색인 토큰화 버전 확인, 재색인 전 기존 검색으로 복귀 |
