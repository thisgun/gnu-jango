# Next.js Default 쇼핑몰·서브페이지 개선 PRD

> **Summary**: 기준 사이트의 핵심 쇼핑몰·게시판 화면을 Django 데이터로 재현하고, 탐색·읽기·구매 진입까지 일관된 경험을 제공한다. 게시판 우측 레일과 목록 행 높이를 기준에 맞추고, 쇼핑몰 설정을 유지하는 네 경로 통합 원본 데이터 fixture를 준비했다. 같은 조건의 화면 캡처와 첨부파일 원본 복구 확인은 계속한다.
>
> **Project**: GNU Jango
> **Version**: 4.4
> **Author**: Codex
> **Created**: 2026-10-08
> **Status**: 네 경로(`/shop`, `/shop/1446772772`, `/free`, `/board/219`)에서 쇼핑몰 설정과 게시판 원본 데이터를 함께 유지하는 격리 DB를 만들었다. 게시판 글·댓글 ID/부모 관계, 자유게시판 전체 순서, 대상 상품의 문의 ID, 화면 응답을 확인했다. 원본 첨부 파일 376건과 네 화면 전체의 동일 조건 시각·역할별 수용은 아직 열려 있다.

## 1. 제품 목표

사용자가 쇼핑몰과 게시판으로 이동해도 `127.0.0.9` 기준의 페이지 구조와 조작 방식을 유지한다. 사이트의 데이터와 상품이 달라도 제목·이미지·가격·검색·댓글·구매 버튼의 배치와 의미를 쉽게 이해할 수 있어야 한다.

**성공 조건은 네 화면의 시각적 일치와 주요 사용자 동작을 각각 충족하는 것이다.** HTTP 200, API 응답, 빌드 성공, 홈 화면 일치만으로 서브페이지를 완료 처리하지 않는다.

- [구현 플랜](nextjs-default-subpages.plan.md)
- [현황 비교 및 캡처](../../03-analysis/nextjs-default-subpages.audit.md)
- 기존 테마 PRD의 FR-03/04/07/10 중 서브페이지 디자인 수용 조건을 이 문서로 보완한다. 기존 권한·정적 서빙·설치/복구 계약은 계속 따른다.

- 구조·스타일 차이, 데이터/설정 차이, API 계약 부족을 각각 기록한다. 차이가 데이터 때문이어도 빈 상태의 디자인과 원본 데이터 전달은 요구사항에 포함한다.
- 자동 재생 슬라이드·로그인 상태·검색 조건·스크롤 위치를 맞춰 비교한다. 최초 로딩이나 임시 not-found 화면은 최종 디자인 근거로 채택하지 않는다.

## 5. 공통 화면 요구사항

### 5.1 커뮤니티 서브페이지

- 넓은 화면에서 기준의 본문과 오른쪽 레일 비율·간격을 맞춘다. 레일은 회원/로그인, 최근 댓글, 인기 검색어 순서를 따른다.
- 목록과 상세의 본문 시작점, breadcrumb, 제목, 카드 경계와 기본 글꼴을 기준에 맞춘다. 데이터가 다른 경우에도 불필요한 제목용 카드와 큰 공백을 추가하지 않는다.
- 작은 화면에서는 기준처럼 본문 우선으로 재배치한다. 레일은 기준의 breakpoint와 하단 배치/숨김 정책을 설계 단계에서 실측해 결정한다.
- 기존 홈 sidebar를 바로 재사용하기 전에 데이터와 역할을 확인한다. 현재 홈의 최근 게시글 위젯과 기준 서브페이지의 최근 댓글 레일은 서로 다르다.

### 5.2 쇼핑몰 공통 틀

- 서비스 전환 바, 상점 로고, 카테고리 버튼/메뉴, 상품 유형 링크, 상품 검색, 회원/장바구니 진입을 기준 순서로 배치한다.
- 상점 로고는 설정된 쇼핑몰 로고를 우선 사용한다. 미설정 시 사용할 기본 상점 자산을 명확히 정하며, 기준의 youngcart 자산을 사용하는 경우 원본 경로/라이선스를 기록한다.
- 커뮤니티 공통 헤더와 현재 상단 분류 바를 중복으로 남겨 세 줄짜리 헤더를 만들지 않는다. 커뮤니티 복귀 시 해당 헤더가 정상 복원된다.
- 상점의 흰 바탕, 따뜻한 중성색, 짙은 녹색 구매 강조, 할인 강조색을 영역 토큰으로 정의한다. 갤러리·옵션 입력처럼 기준이 둥근 요소와 상품 행처럼 각진 요소를 구분한다.
- 포털에 렌더링되는 옵션 담기·갤러리·후기 모달도 상점 토큰을 사용한다. 기존 밝음/어두움 선택은 보존하며 어두운 화면 가독성은 별도로 확인한다.
- 사업자·연락처·약관·저작권은 현재 사이트 설정을 사용한다. 설정이 없는 값은 가짜 정보로 채우지 않는다.

## 6. 쇼핑몰 홈

### 구성 순서

상점 헤더 → 화면 폭을 사용하는 대형 배너 → 분류 캐러셀 → 히트상품 → 최신상품 → 추천상품 → 할인상품 → 인기상품 → 고객 후기 → 공지/고객센터/입금 안내 → 상점 푸터. 영역 활성화 여부와 데이터 없음 정책은 운영 설정으로 정하며, 활성화되고 데이터가 있는 영역은 기준 순서로 표시한다.

### 상세 요구사항

- 배너는 이미지를 적절히 자르고 제목/설명/연결 행동을 읽을 수 있게 한다. 기준 배너에서 문구가 이미지에 포함돼 있는지 확인해 중복 문구를 얹지 않는다.
- 이전/다음, 진행 표시, 현재/전체 수, 재생/정지, 키보드/터치 조작을 제공한다. 배너가 0개이거나 이미지가 모두 실패하면 순환 조작을 숨기고 상점 안내와 상품 목록 진입을 표시한다. 1개일 때도 불필요한 순환 조작을 숨기며, 모션 감소 설정에서는 자동 재생을 시작하지 않는다.
- 분류의 아이콘·명칭·선택/hover·이동 조작을 기준에 맞춘다. 분류가 많아도 본문 전체가 가로로 넘치지 않는다. 실제 Django 분류명과 계층을 사용한다.
- 상품 행은 기준의 제목/보조 문구/전체 보기/이전·다음, 카드 폭·간격·부분 노출 방식으로 구성한다. 지금의 추천상품 여러 줄 격자를 기준의 한 줄 탐색 구성으로 맞춘다.
- 카드는 사진, 브랜드/분류, 두 줄 상품명, 가격/할인, 실제 평점·리뷰 수, 담기 조작의 높이를 정렬한다. 리뷰가 0개라면 없는 평점을 만들어 표시하지 않는다.
- 상품 종류 배지는 PHP `item_icon()`의 유형 1~5와 활성 쿠폰 배지를 원문 라벨·순서로 가격 아래에 표시한다. 쿠폰은 유효 기간 안에 있고 상품 또는 상품 분류를 대상으로 하는 경우에만 표시한다.
- 담기 조작은 필수 옵션이 없는 상품과 있는 상품을 구분한다. 옵션 상품은 카드에서 연쇄 선택지를 고른 뒤 카트에 담으며, 품절·재고·최소/최대 수량을 반영하고 진행 중/실패/성공 상태를 제공한다.
- 고객 후기는 실제 공개 후기만 표시하며 상품 상세의 해당 후기와 연결한다. 실제 공지·고객센터·입금 설정을 표시하고 없는 영역의 정책을 명시한다.

## 7. 상품 상세

- 넓은 화면의 주 사진/구매 패널 비율과 간격을 기준에 맞춘다. 기준 소스의 712:440 비율과 64px 간격을 출발점으로 삼되, 실제 기준 DOM과 breakpoint를 S0에서 확인한다. 현재 두 영역을 같은 폭으로 놓는 구성을 조정한다.
- 주 사진, 이전/다음, 썸네일 선택, 확대 모달을 제공한다. 사진 1개/여러 개/없음/실패 상태를 각각 처리하며 앱 아이콘을 정상 상품 사진으로 취급하지 않는다.
- 브랜드/분류 → 제목과 공유 → 부제 → 평점/후기 → 가격 → 배송·상품 기본 정보 → 옵션/수량 → 선택 항목과 총액 → 카트/바로구매/찜 → 이전·다음 상품 순서와 구획을 맞춘다. 값이 없는 필드만 생략한다.
- 옵션 제목은 실제 상품의 이름을 사용한다. 앞 단계 선택에 따라 다음 단계 선택지를 갱신하고 불가능한 선택·품절·최소/최대 수량을 안내한다.
- 선택 옵션은 이름·수량 증감·추가금·삭제를 제공한다. 총액은 기존 계산과 서버 검증을 유지한다. 실패 후 입력 상태를 보존하고 중복 제출을 방지한다.
- 상품설명/상품후기/상품문의/배송정보 탭, 선택 상태, 실제 건수와 빈 상태를 제공한다. 설명 이미지와 표는 화면 폭에 맞추고 필요한 표만 영역 안에서 스크롤한다.
- 넓은 화면의 탭/본문 옆 구매 보조 패널은 상단 구매 패널과 같은 상태를 공유한다. 모바일에서는 같은 패널을 그대로 중복 노출하지 않는다. 모바일 구매 진입은 기준에 맞춰 설계하고 기존 하단 메뉴와 겹치지 않게 한다.
- 최근 본 상품과 관련 상품은 현재 데이터로 구성한다. 기준과 데이터 수가 다르면 카드 수까지 같게 만들지 않는다.
- 찜·문의·후기 작성 등 인증 동작은 안전한 내부 복귀 주소로 로그인에 연결한다. 실결제나 추천 메일 발송은 이번 수용 확인에 포함하지 않는다.

## 8. 게시판 목록

- breadcrumb → 제목/글 수/현재 쪽과 글쓰기 → 분류가 있는 목록 카드 → 쪽 이동 → 검색 순서를 기준에 맞춘다. 기준 CSS의 화면 순서와 실제 DOM 읽기 순서가 크게 달라지지 않도록 마크업도 정리한다.
- 데스크톱 열 순서는 번호·제목·글쓴이·조회·날짜를 따른다. 관리자 선택 칸은 권한이 있는 경우에만 표시한다.
- 공지는 옅은 강조 행과 기준의 공지 표시를 사용한다. 현재 빨간 공지 badge와 일반 표의 차이를 정리한다. 제목·댓글 수·새 글/첨부/비밀글 표시도 현재 게시판 설정에 따른다.
- 모바일에서는 제목 아래 작성자/조회/날짜를 재배치한다. 열을 숨기는 것만으로 중요한 메타정보를 없애지 않는다. 긴 제목은 적절히 줄바꿈/줄 수 제한하고 상세에서 전체 내용을 읽을 수 있게 한다.
- 검색 대상·검색어·분류·쪽 이동 상태를 URL과 함께 보존한다. 검색 또는 분류 변경 시 적절한 첫 쪽으로 이동하고 뒤로 가기/새로고침에도 상태를 유지한다.
- RSS와 기존 키보드 탐색 기능을 유지하되 기준에 없는 큰 안내 줄을 목록 위에 상시 표시하지 않는다. 실제 글 수가 많은 것은 데이터 차이이며 임의로 줄이지 않는다.

## 9. 글 상세

- 게시판명/목록 → 글 카드의 분류·글 번호·제목 → 작성자/게시 시각/조회/댓글/공유·권한 액션 → 본문 → 첨부/관련 링크 → 반응 → 댓글 진입/답글/글쓰기/목록 → 댓글 → 이전·다음 → 설정에 따른 하단 목록으로 구성한다.
- 제목은 모바일에서 본문 폭을 충분히 사용한다. 수정·삭제·스크랩은 별도 줄이나 기준의 재배치로 처리해 제목을 좁은 칼럼에 밀어 넣지 않는다.
- 날짜·조회·이전글/다음글·목록·글쓰기를 한국어로 통일한다. 현재 `Views`, `Previous`, `List`, `Write`는 대상이다. 게시글 원문 자체는 번역하거나 바꾸지 않는다.
- 원문 HTML은 기존 정제·안전한 링크 규칙을 유지한다. 이미지/동영상/표/코드/긴 URL이 본문을 넘치지 않게 한다. 캡처 속 외부 콘텐츠를 새로 재생하거나 외부 링크를 방문할 필요는 없다.
- 첨부는 이름·크기·다운로드 상태와 권한을 표시한다. 첨부가 없는 대상 글에 기준 파일을 추가하지 않는다.
- 추천·비추천·스크랩·공유는 게시판 설정/권한에 따라 표시하고 실제 상태와 실패 안내를 제공한다. 게시글의 소유자 또는 관리자가 아닌 사용자에게 수정·삭제를 제공하지 않는다.
- 댓글은 0개/여러 개/답글/비밀/삭제 상태와 작성 권한을 처리한다. 실제 댓글 편집기 설정을 사용한다. 기준 글의 댓글 8개와 대상 글의 0개는 데이터 차이로 기록한다.
- 하단 목록은 게시판의 상세 목록 표시 정책을 따른다. 지원 설정이 없으면 S1 계약에 포함해 기준의 상세 탐색을 제공한다. 목록 복귀 시 검색·쪽 위치를 보존한다.

비회원은 게시판의 글쓰기·답글·댓글 등급이 허용할 때 이름과 비밀번호를 입력해 작성할 수 있다. 서버는 등급과 CAPTCHA를 확인하고 비밀번호를 해시해 저장한다. 로그인 사용자에게는 비회원용 입력을 요구하지 않는다.

| 후기/문의 | 실제 건수·평점·공개 범위·페이징 | 실제 승인 후기만 공개 API에 반환하고 평점/후기 수를 사용. 데이터 없음과 권한 부족을 구분 |
| 상점 안내 | 회사·연락처·운영 시간·입금 안내·약관 링크 | 현재 설정을 조사해 재사용. 미설정 값의 표시/숨김 정책 정의 |
| 게시판 표시 | 분류·공지·권한·글/댓글 편집기·상세 하단 목록 정책 | 기존 설정 재사용, 누락 계약만 추가 |

관리자에서 배너를 바꾸면 테마 전체 재빌드 없이 공개 화면에서 갱신되어야 한다. 현재 서버 응답은 300초 재검증 주기를 사용한다. DB migration은 추가했지만 이 문서 작성 중에는 DB에 적용하지 않았다.

## 12. 수용 기준

### AC-V: 시각적 일치

| ID | 조건 |
|---|---|
| AC-V1 | 네 화면 각각 3개 폭에서 상단·본문/상품 행·댓글/탭·하단을 같은 상태로 비교. 필수 영역의 누락·순서·잘못된 shell·색상 계층 차이 0건 |
| AC-V2 | S0에서 정한 DOM 기준점의 본문 폭/시작점·칼럼 비율·gap·주 이미지/배너 높이·버튼 높이를 측정. 같은 조건 fixture에서 주요 치수 차이 ≤4 CSS px, 글자 크기 차이 ≤1px, 이미지 비율 차이 ≤2%를 초기 목표로 적용. 글 내용 길이에 따른 문서 총높이는 비교 대상에서 제외 |
| AC-V3 | 긴 제목/URL·이미지 없음/실패·0개 결과·로딩/오류에도 겹침·의도치 않은 잘림·문서 가로 넘침 없음. 기준에 필요한 기능과 접근성 때문에 다른 부분은 사유/대안/범위를 기록 |
| AC-V4 | At 390px, 768px, and 1440px, document width equals the viewport; author, views, and date columns do not overlap or wrap unnecessarily. |

허용 오차는 아직 측정 결과가 아니라 구현 목표다. 글꼴 렌더링·브라우저 차이는 S0에서 조정하고 조정 사유를 남긴다. 서로 다른 콘텐츠 전체의 이미지 차이 비율 하나만으로 합격시키지 않는다.

## 13. 확인 데이터와 증거 관리

- 게시판: 짧은/긴 한국어·다국어 제목, 공지·분류·첨부 이미지/파일, 댓글 0/여러 개/답글, 비밀글과 권한 제한.
- 상품: 사진 0/1/여러 개/실패, 단순·연쇄·추가 옵션, 할인·전화문의·품절, 설명 있음/없음, 후기·문의 0/여러 개. 원본 옵션 테이블 782행 중 로컬에 해당 상품이 있는 488행을 이관했다. 동일 상품 fixture `1446772772`에는 크기·색상 선택 9개 조합이 있다.
- 상점 홈: 배너 0/1/여러 개, 분류 소수/다수, 상품 행 0/1/여러 개, 안내 설정 있음/없음.
- 사용자: 비회원, 일반 회원, 글 소유자/다른 회원, 관리자. 주어진 관리자 계정을 비교 스크린샷의 일반 방문자 기준으로 사용하지 않는다.
- 각 증거에는 URL·폭·역할·데이터 조건·상태·빌드 식별·확인 날짜·요구사항 ID를 남긴다. 기준/대상을 같이 보고 판정한다.
- 기존 DB는 보존한다. 테스트 레코드가 필요한 수용 작업은 복제 환경에서 수행하며 계정·원문·다운로드 토큰이 포함된 캡처/DOM은 gitignored 로컬 폴더에 저장한다.

## 15. 게시글 답글 호환성 보완

- `wr_reply`는 그누보드와 같은 최대 10자 문자 경로로 저장한다. 답글은 `bo_reply_order` 설정에 따라 A→Z 또는 Z→A를 배정하고, 목록은 원본처럼 `wr_reply` 오름차순으로 표시한다.
- 각 글의 원본 `wr_id`는 `legacy_wr_id`에 보존하고 `wr_parent`에는 원본 스레드 루트 ID를 유지한다. 상세·스크랩 조회도 원본 ID와 신규 Django ID를 모두 처리한다.
- 기존 숫자 답글 순서를 문자 경로로 변환하는 데이터 마이그레이션을 추가했다. 0은 원글의 빈 경로로 바꾸고, 기존 가져오기 데이터의 원글 번호를 복구한다. 역방향 마이그레이션도 숫자 순서를 복원한다.
- 원본 데이터 가져오기는 원본 글 ID로 반복 실행 가능한 upsert를 수행하고, 답글 경로와 부모 ID를 보존한다.
- API 검증은 신규/중첩 답글, 두 답글 순서 설정, 한 단계 26개 제한, 깊이 10 제한, 가져온 글의 주소/부모 연결을 다룬다. 현재 로컬 DB 5,629개 글은 보존됐고 원본 ID가 연결됐다. 기존 로컬 DB에는 답글이 없어 변환 표본은 별도 회귀 검사로 확인했다.
- 비회원 글과 답글은 게시판 등급, CAPTCHA, 이름·비밀번호 입력을 확인하고 비밀번호를 해시해 저장한다. 잘못된 CAPTCHA는 글을 만들지 않으며, 유효한 코드는 한 번 사용한 뒤 폐기된다.
- CAPTCHA는 같은 코드에서 6회 오답 뒤 잠기며, 새 이미지 발급 시 오답 수를 초기화한다. 이 제한은 회원 가입 CAPTCHA에도 적용된다.
- 네 화면의 같은 데이터 시각 비교, 역할별 전체 수용, 누락 첨부 복구는 별도 P0 미완료 항목으로 남는다.

## 16. 스레드 삭제와 첨부 경로

- 게시글 삭제 API는 원본 스레드 ID와 `wr_reply` 경로로 대상 답글을 찾고 깊은 답글부터 정리한다. 일반 작성자는 답글이 남은 원글을 삭제할 수 없고, 관리자는 해당 스레드의 각 답글 관리 권한이 있을 때 스레드를 삭제할 수 있다. 답글 한 건 삭제 시에는 해당 답글의 하위 경로만 정리한다.
- API는 삭제된 원본 글 ID 목록을 반환한다. Next.js 일괄 삭제 화면은 목록에서 이미 삭제된 답글을 숨기고 중복 요청을 건너뛴다.
- 회귀 검사는 별도 레거시 `wr_id`를 가진 원글/중첩 답글, 하위 답글 선택 삭제, 댓글·첨부 정리, 게시판 경계, 관리자 등급을 다룬다. 관련 15개 Django 테스트, Next.js 타입 검사와 정적 빌드/동기화가 통과했다.
- 현재 원본 디렉터리에서 경로가 정확히 확인된 첨부 17개는 overwrite 없이 Django 미디어의 기존 `data/file/...` 경로에 복사했다. 원본과 SHA-256이 같고 8081에서 17개 모두 HTTP 200이다. 이 17개는 이미 다른 저장 경로로 제공되던 참조와 겹친다. 전체 393건 중 370건은 여전히 원본 파일이 없으며, 원본 업로드 바이트의 해시 확인도 미완료다.
