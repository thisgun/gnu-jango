# PRD: 실시간 알림

## 사용자 요구

회원은 댓글·쪽지·주문 상태 변화를 페이지를 새로 열지 않고 확인한다. 관리자는 지정 회원, 스태프 또는 활성 회원에게 공지를 보낸다.
일반 웹 호스팅에서도 기존 알림함을 계속 이용한다.

## 기능 요구와 수락 기준

| 기능 | 기준 |
|---|---|
| 댓글 | 원글 작성자와 답댓글의 부모 댓글 작성자에게 각각 한 건. 같은 수신자는 중복 제거하고 본인이 쓴 댓글은 본인에게 알리지 않는다. 비회원 작성도 지원한다. |
| 쪽지 | 수신 사본 생성 시 수신자에게 한 건. 발신 사본과 수정에는 추가하지 않는다. |
| 주문 | 회원 주문의 실제 상태 변경 시 한 건. 초기 주문, 동일 상태 재저장, 영문/한글의 동등한 상태 변경, 비회원 주문은 제외한다. |
| 공지 | `core.add_notification` 권한을 가진 관리자만 발송한다. 활성 회원만 대상으로 하고 요청당 최대 500명. 확인 체크, DB 요청 ID로 중복 방지, 관리자 이력을 남긴다. |
| 실시간 전송 | 로그인 사용자 본인의 그룹에 DB 커밋 후 전달한다. 롤백된 알림은 전송하지 않는다. |
| 인증 | 접속권은 30초, 한 번만 사용. 최초 5초 안에 첫 프레임으로 인증한다. URL에 토큰을 넣지 않는다. |
| 연결 수명 | 최대 약 5분, 주기적 인증 재검사. 로그인 만료/폐기/비활성화 후 연결을 닫는다. |
| 개인정보 | 댓글·쪽지 본문과 주문 개인정보를 자동 알림에 복사하지 않는다. 소켓에는 변경 신호만 전달한다. |
| 복구 | 연결/재연결 시 REST 재조회. 장애 시 가시 탭에서 60초 폴링, 연결 중에도 5분마다 동기화. |
| 호환성 | 기존 REST 응답 형식 유지. Channels 미설치·비활성 환경에서도 Django WSGI 실행 가능. |

## 비기능 요구

- Redis는 인증·TLS·네트워크 제한을 적용한다. 애플리케이션과 Preview의 키 공간을 분리한다.
- 전달 실패 로그에는 오류 종류만 기록한다. 접속권·JWT·Redis 주소·알림 본문은 기록하지 않는다.
- Redis 전달은 최선의 시도이며, DB 알림함이 최종 기준이다. exactly-once 스트리밍이나 오프라인 모바일 푸시는 약속하지 않는다.
- Redis 장애가 이미 저장된 결제·댓글을 되돌리지 않게 한다. 전송은 최대 2초 내 중단하고 REST가 복구한다.
- 웹 요청 중에는 Redis 전송을 기다리지 않는다. 전용 작업자가 대기열을 처리하고 실패는 간격을 늘려 재시도한다.
- 알림 생성 실패가 원본 결제 확정 트랜잭션을 롤백시키지 않는다. 원본 커밋 후 대기열에 저장된 작업은 재시도하되, 커밋과 대기열 기록 사이의 프로세스 종료까지 보장하지는 않는다.
- 과거 자료 가져오기와 샘플 생성은 기본적으로 자동 알림을 억제한다. 요청별 억제로 동시 회원 요청을 방해하지 않는다.
- 오래된 데이터의 소급 알림을 만들지 않는다. `bulk_create`, `QuerySet.update`는 신호를 우회하므로 공지 서비스처럼 명시적으로 전달하거나 일반 `save` 경로를 이용한다.

## 제외 범위

- Expo 앱 신규 제작, OS 푸시 권한·기기 토큰 관리, FCM/APNs 계정 생성.
- 이메일/SMS 전송, 실시간 채팅, 결제 로직 변경, 기존 서버와 DB에 대한 배포 실행.
