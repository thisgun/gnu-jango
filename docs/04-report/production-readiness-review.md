# 프로덕션 준비도 점검

점검일: 2026-10-15

## 범위

외부 리뷰의 지적을 저장소 설정과 현재 공개 handbook API에 대조하고, 재현 가능한 빌드·버전 관리 문제를 우선 보완했습니다. 이 문서는 독립적인 보안 감사나 결제 운영 승인을 뜻하지 않습니다.

## 이번에 보완한 항목

- Python 기준을 3.12로 통일했습니다. `.python-version`, Docker 이미지, CI, Ruff 설정, README가 같은 기준을 사용합니다. CI가 이미 3.12에서 Django 의존성을 설치하고 있으므로 이 버전을 기준으로 삼았습니다.
- 정적 Next.js 빌드 작업 공간을 고정된 이름으로 사용하게 했습니다. 이전에는 임의 경로가 Turbopack 산출물 이름에 반영되어 같은 소스도 매번 다른 파일을 만들었습니다. 빌드 잠금과 경로 검증을 유지하고, 전용 작업 공간만 빌드 전후 정리합니다.
- CI는 `ensure_handbook_samples --stable-dates`로 게시판과 고정 게시일을 준비한 후 두 테마를 각각 빌드하고, 커밋된 Django 테마 파일과 비교합니다. 비교 전에 파일을 동기화하지 않으므로 오래된 번들이 CI를 통과하지 않습니다.
- 기본 테마와 handbook 테마를 재생성했습니다. 반복 빌드와 산출물 동기화 확인이 모두 통과했고, handbook 번들에 비회원 댓글 CAPTCHA 코드가 포함됐습니다.
- Django 정적 테마 폴더는 배포에 필요한 생성물로 유지합니다. `.next` 임시 빌드 폴더와 달리 Django 배포가 직접 서빙하는 파일입니다. 정해진 handbook 샘플에서 생성되지 않는 오래된 RSS 내보내기 파일은 정리했습니다.

## 운영 전에 필요한 추가 확인

1. **결제**: Toss 테스트 키로 승인·실패·가상계좌 입금 대기·만료·취소 흐름을 전체적으로 확인하고, 중복 콜백과 재시도에 대한 멱등성 및 대사 결과를 검증해야 합니다. 이번 점검에서는 결제 E2E를 수행하지 않았습니다.
2. **데이터 이전과 복구**: 실제 그누보드 원본과 행 수·관계·첨부 파일을 대조하고, 백업에서 새 환경으로 복구하는 절차를 실행해야 합니다. 마이그레이션 개수만으로 데이터 동등성이 확인되지는 않습니다.
3. **의존성 취약점**: `npm audit`에서 잠금 파일 기준 7건(높음 5, 보통 2)이 보고됐습니다. 운영 의존성 검사에서도 `@tailwindcss/typography`를 통한 보통 등급 2건이 남았습니다. 자동 수정이 현재 Next ESLint 버전을 크게 낮추는 선택을 제안해 강제 적용하지 않았습니다. 호환성을 확인하며 직접 업데이트해야 합니다.
4. **성능과 서버리스 DB 연결**: Vercel 함수와 Supabase 조합의 콜드 스타트, 동시 연결 수, 느린 쿼리를 실제 트래픽 조건에서 측정해야 합니다. 현재 응답 성공만으로 쇼핑몰 부하를 감당한다고 판단할 수 없습니다.
5. **테스트와 보안 검토**: Django 커버리지 실측, 운영자 권한·개인정보·결제 경로에 대한 독립 검토가 필요합니다. LGPL 표기와 원본 프로젝트 코드·자산의 라이선스 의무도 출처별로 확인해야 합니다. 이 점검에서는 법률 판단이나 전체 테스트 실행을 하지 않았습니다.

## 판단 기준

현재 상태는 데모·학습·포팅 검토에는 적합하지만, 실결제와 민감한 회원정보를 맡기는 운영 대체재로 승인할 증거가 아직 부족합니다. 위 다섯 항목의 결과를 기록하고 운영 책임자가 검토한 뒤 배포 범위를 결정해야 합니다.
