# 쇼핑몰 데모 상품 노출 개선

작성일: 2026-10-14

## 원인과 운영 데이터 보정

운영 `/api/v1/shop/products`에는 샘플 상품 6개가 있었지만 `it_type1`~`it_type5` 값이 모두 비어 있었다. 쇼핑몰 메인은 상품 유형별로 조회하므로 전체 상품 목록에만 존재하고 메인에는 표시되지 않았다.

생성 기록에 등록된 상품만 대상으로 기존 유형 보정 기능을 실행했다. 보정 전 manifest와 변경 필드는 저장소 밖 `local-notes/shop-demo-before-20261014.json`에 저장했다.

- 히트·추천·신상품·인기상품: 각각 6개
- 할인상품: 2개
- 실제 운영 화면: 상품 카드 26개, 고유 상품 6개
- 첫 상품 상세: HTTP 200, 처리되지 않은 JavaScript 오류 없음

## 재발 방지

- `/admin/sample-data/`에 관리 상품·공개 상품·진열 미지정·비공개·누락 상품 수와 유형별 메인 노출 수를 표시한다.
- **쇼핑몰 샘플 추가·복구 및 노출 적용** 버튼을 추가했다. 커뮤니티 샘플을 삭제하지 않고 쇼핑몰 상품 6개를 준비할 수 있다.
- 반복 실행하면 기존 샘플을 재사용한다. 슬롯별 상품 ID를 manifest에 기록해 일부 상품이 없어져도 나머지 슬롯의 할인 설정을 바꾸지 않고 빠진 상품을 채운다.
- 상품·카테고리·배너는 생성 기록으로 범위를 제한한다. 기존 샘플 상품의 판매가·재고·설명·이미지는 유지하고, 메인 유형·판매 활성화·관리 중인 샘플 분류를 적용한다.
- 새 전체 샘플 생성도 같은 쇼핑몰 준비 함수를 사용한다. 삭제 시 실제 주문·후기 등이 연결된 샘플을 보존하는 기존 동작은 유지한다.
- 쇼핑몰 메인에 유형별 진열이 하나도 없으면 공개 상품을 **전체 상품**으로 표시한다. 유형을 지정하지 않은 일반 상품을 히트상품으로 표시하지 않는다.
- API의 기존 판매 활성화·분류 공개 조건을 재사용한다. 비공개 상품을 표시하는 우회 처리는 없다.
- 기존 최적화 WebP 7개를 재사용한다. 신규 이미지 업로드나 외부 이미지 의존성을 추가하지 않았다.

## 관리 명령

```powershell
# 현황 조회
python manage.py ensure_shop_samples

# 쇼핑몰 샘플 추가·복구 및 노출 적용
python manage.py ensure_shop_samples --apply
```

운영 보정 후 새 관리 명령도 적용했으며 상품 추가·변경 없이 6개가 정상 준비된 상태임을 확인했다. DB 마이그레이션은 필요하지 않다.

## 확인

- Django 설정 검사 통과.
- 관리자 템플릿 렌더링 HTTP 200, 노출 진단과 새 작업 버튼 표시 확인.
- Next.js 타입 검사·린트·정적 테마 빌드 및 동기화 검사 통과.
- 운영 상품 조회와 실제 브라우저 화면에서 6개 상품의 메인 진열 및 첫 상품 상세를 확인했다.

운영 반영 후 `/admin/sample-data/`의 새 버튼으로 같은 보정을 반복할 수 있다.
