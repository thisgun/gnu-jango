# 데모 안내 페이지 누락 보강과 오류 안내

## 원인

`/content/company`, `/content/privacy`의 HTML 화면은 열리지만, 해당 DB 레코드가 없으면 콘텐츠 API가 `404 content_not_found`를 반환한다. 기존 프론트엔드는 이 응답도 서버 장애와 같은 문구로 표시했다.

## 변경

- 관리자 `/admin/sample-data/`에 **데모 안내 페이지** 영역을 추가했다. 사이트 소개(`company`), 개인정보처리방침(`privacy`), 이용약관(`provision`)의 미등록·비공개·본문 없음·공개 상태를 확인할 수 있다.
- **누락된 데모 안내 페이지 추가**는 없는 페이지만 생성한다. 기존 본문과 공개 설정은 유지한다. 비공개 페이지를 임의로 공개하지 않는다.
- 생성한 페이지만 기존 샘플 관리 기록에 ID와 스냅샷을 남긴다. 직접 등록한 페이지는 샘플 삭제 대상에 넣지 않는다. 기존 삭제 로직은 수정된 샘플 페이지를 보존한다.
- 페이지를 복구할 때 기존 추적 ID와 스냅샷이 중복되지 않게 한다.
- 안내 페이지만 먼저 준비해도 나중에 전체 게시판·상품 샘플을 추가할 수 있도록 커뮤니티 샘플 판정을 조정했다.
- 프론트엔드에서 404 또는 정상적인 빈 결과는 미등록·비공개 안내로, 서버·연결·응답 형식 오류는 불러오기 실패 안내로 구분한다. 오류 응답의 내부 정보는 화면에 노출하지 않는다.
- 일시적 오류에는 **다시 시도**, 모든 오류에는 **홈으로 이동**을 제공한다. 이전 요청 결과가 다른 페이지나 재시도 결과를 덮어쓰지 않도록 정리한다.

## 사용 방법

```bash
# 변경 없이 현재 샘플과 안내 페이지 상태 확인
python manage.py ensure_demo_samples

# 안내 페이지 중 빠진 페이지만 추가
python manage.py ensure_demo_samples --ensure-content
```

이 명령은 게시판·상품·메뉴를 추가하지 않는다. 관리자에서도 같은 작업을 실행할 수 있다. 개인정보처리방침과 이용약관은 데모용 예시로 표시하며 실제 서비스의 정책으로 간주하지 않는다.

## 적용 범위

DB 마이그레이션은 필요하지 않다. Django에 포함되는 프론트엔드 변경은 `nextjs_default`, `handbook` 각각의 `theme`·`theme_static` 빌드 결과를 함께 배포해야 반영된다. PythonAnywhere에서는 코드 갱신 뒤 필요한 정적 파일 수집과 Web 앱 Reload를 수행한다.

정적 내보내기에서는 화면 HTML의 HTTP 상태가 200일 수 있다. 이번 변경은 콘텐츠 API의 404와 사용자 안내를 구분하며, 서버에서 내려주는 HTML 상태 코드를 바꾸지는 않는다.

## 작업 결과 (2026-10-23)

- `nextjs_default`, `handbook`의 정적 빌드와 빌드에 포함된 TypeScript 처리가 완료됐다. 운영용 `theme`·`theme_static` 파일을 함께 갱신했다.
- 별도 자동 테스트는 추가하거나 실행하지 않았다.
- 공개 데모 DB에 빠져 있던 `provision` 데모 예시를 추가하고 검색 색인에 반영했다. 기존 `company`, `privacy` 레코드는 보존했다.
- 관리자 버튼과 새 오류 안내 코드는 커밋·배포 후 공개 사이트에 적용된다.
