# 쇼핑몰 설정 통합

- 주소: `/admin/shop-settings/`
- 관리자 사이드바 운영 메뉴의 **쇼핑몰 설정**, 기본환경설정 화면의 **쇼핑몰 결제·배송 설정** 링크에서 접근합니다.
- 최고관리자만 조회·저장할 수 있으며 Django admin 인증과 CSRF 보호를 사용합니다.

## 관리 항목

- 무통장입금 사용 여부와 입금계좌
- 카드, 가상계좌, 실시간계좌이체, 휴대폰, 간편결제 허용 여부
- 현금영수증 신청 사용 여부와 무통장·가상계좌·계좌이체별 허용 여부
- 쇼핑몰 회사명·고객센터, 택배사·구간별 배송비, 배송·교환 안내
- 포인트 결제 한도·단위, 혼합 과세, 후기 작성·승인 정책
- 현재 주문 화면에서 사용 가능한 결제수단 및 PG 키 등록 여부·테스트/실결제 모드

PG 키는 서버 환경 변수로 관리하며 관리자 화면에는 키 값이 전달되지 않습니다. 키 누락·부분 등록·잘못된 접두사·테스트/실결제 키 혼합을 구분하고, 한 모드의 키 쌍만 결제 설정으로 인정합니다. 관리자가 요청하면 임의 주문 ID를 이용한 읽기 전용 API 조회로 인증을 확인합니다. 결제나 취소는 실행하지 않습니다.

계좌·운영 설정은 기존 Config와 ShopShippingPolicy(id=1)에 함께 저장됩니다. 고객센터 전화번호는 쇼핑몰 설정, 기본환경설정, 기존 배송정책 관리 화면에서 저장해도 양쪽 저장소가 동기화됩니다. 저장 이력에는 계좌나 비밀값을 넣지 않습니다. 새 DB 마이그레이션은 필요하지 않습니다.

## 주문 반영

기존 `/api/v1/shop/payment/config` 형식을 유지하면서 관리자 허용 여부와 실제 PG 준비 여부를 함께 적용합니다. PG 환경 변수가 없는 경우 체크박스를 켜도 온라인 결제가 활성화되지 않습니다. 기존 설치의 온라인 결제수단은 기본 허용값으로 동작합니다.

주문 생성에서도 중지한 수단을 거부합니다(`payment_method_disabled`). 이미 생성된 주문의 PG 승인·입금 웹훅·취소 처리는 설정 변경으로 차단하지 않습니다. Config는 직접 조회하므로 새 요청에 반영됩니다.

현금영수증 설정은 주문 화면 표시와 주문 API 검증에 함께 적용됩니다. 무통장입금은 소득공제·사업자 지출증빙 요청 유형을 주문에 기록하고 관리자가 수동 처리합니다. 토스 가상계좌·계좌이체는 고객이 선택한 발급 유형과 식별번호를 토스 SDK에 전달합니다. 식별번호는 결제 준비 요청에서 형식을 검증하고 브라우저로 돌려보내지만 ShopOrder에는 저장하지 않습니다. 결제 승인 또는 가상계좌 입금 응답에 발급 번호·영수증 주소가 포함되면 주문에 저장합니다. 발급 정보가 오지 않은 경우 주문 상세에 영수증 링크를 표시하지 않습니다.

세금계산서 요청에는 상호명·사업자등록번호·수신 이메일이 필요합니다. 서버가 입력 형식을 확인하고 주문에 저장하며, 관리자는 주문 상세에서 요청 정보를 확인할 수 있습니다. 세금계산서의 실제 발행은 아직 PG/API와 연결되지 않아 관리자가 별도로 처리해야 합니다. 무통장입금의 현금영수증도 자동 발행하지 않으며, 번호가 필요한 경우 관리자가 주문자에게 추가 정보를 받아 처리해야 합니다. 결제 로그는 사업자번호, 이메일, 연락처, 현금영수증 식별번호 등을 마스킹합니다.

주문에 현금영수증 유형과 세금계산서 수신 정보를 추가하는 마이그레이션 `0028_shoporder_receipt_details`가 필요합니다.

배송비 상한·비용의 개수, 금액·오름차순, 무통장입금 계좌 필수 입력, 포인트 음수·0 단위를 저장 전에 검사합니다. 관리 페이지에는 기본 배송비 구간 미리보기가 있고 저장 버튼은 스크롤 중에도 표시됩니다. 미리보기는 공통 기본 배송비만 계산하며 상품별 배송비와 지역별 추가 배송비는 제외합니다.

## 배포 시 운영자 설정

토스페이먼츠 사용에는 `SHOP_TOSS_CLIENT_KEY`, `SHOP_TOSS_SECRET_KEY`가 필요하며, `SHOP_PAYMENT_PROVIDER=toss`로 선택합니다. 환경 변수 변경 후 재시작/재배포해야 합니다. 가상계좌는 [운영 설정](../../04-deploy/toss-virtual-account.md)의 웹훅 준비 후 서버 허용 플래그도 켭니다.

이 작업은 화면과 연결 로직을 추가하며 실제 PG 키 등록이나 결제를 수행하지 않습니다.

## 실행한 점검

- `.venv314`의 `manage.py check`: 문제 없음 (기존 silenced 1개)
- 설정·결제 API 회귀 테스트 166개 통과; 최종 관리자 페이지 테스트 14개 통과
- 배송비 미리보기 JavaScript 구문 검사와 `git diff --check` 통과
- Toss API 연결 테스트는 모의 응답으로 확인했습니다. 실제 키 인증·결제는 수행하지 않았습니다. 커밋·배포 전 로컬 구현 상태입니다.

현금영수증 유형·식별번호와 세금계산서 수신 정보 추가분의 검증(2026-10-16):

- `gnu_jango/core/test_shop_receipt_requests.py`(14개): 세금계산서 저장·형식 거부, 비회원 신청 거부, 계좌이체 식별번호 규칙(소득공제 8~30자리, 지출증빙 10자리), 식별번호는 결제 준비 응답으로만 돌려주고 주문에 저장하지 않음, 관리자 설정(전체·수단별)에 따른 거부, 무통장 신청 기록, 토스 승인 시 발급 번호·영수증 주소 저장(취소 영수증 무시), 결제 로그 마스킹.
- 검증 중 고친 것: 영수증 링크는 http(s) 주소일 때만 내보낸다. `migrate_gnuboard5`가 `od_cash_res`에 그누보드 `od_cash_info`(PG 응답 텍스트)를 넣기 때문에, 링크 조건을 넓힌 뒤로 이전된 주문에서 그 텍스트가 링크 주소로 나갔고 PG 응답의 `javascript:` 주소도 저장될 수 있었다. 또 비회원의 숨겨진 세금계산서 선택이 주문 검증을 막지 않도록 회원 주문에만 검사한다(주문 본문도 회원에게만 보낸다).
- 프런트 주문 스펙 39개, 결제·주문 Django 테스트, 격리 DB 사본에서 회원 무통장 주문을 화면으로 제출해 세금계산서 수신 정보와 현금영수증 유형(지출증빙)이 주문에 저장되는 것을 확인했다. 토스 가상계좌·계좌이체의 실제 PG 발급은 테스트 키로 확인하지 못했다.
