# 검색 정확도·권한·속도 점검 결과

점검일: 2026-10-21 (한국 시간)

## 범위와 반영 상태

현재 데모에 등록된 게시글 18건·상품 6건, 핸드북 49개 장을 대상으로 공개 검색을 측정했다. 이 자료는 설명용 샘플이며 실제 고객의 검색 로그가 아니다. 정답표는 결과 측정 전에 제목·자료 종류·게시판을 기준으로 정했다.

초기 측정의 운영 코드 기준은 `efa8f50bfb12c25660898bfcd1a0e04271ea91ea`이다. 개선 커밋 `b199b6d5e`는 [PR #48](https://github.com/thisgun/gnu-jango/pull/48)로 병합했으며 **두 Vercel 운영 사이트에 배포하고 공개 HTTP 재측정을 완료했다**. 배포 후 결과는 5절에 기록했다. 권한·검색 설정은 변경하지 않았고, 핸드북의 점수 설명 한 장만 이전 자동 생성 본문과 일치하는지 확인한 뒤 갱신했다. 권한 검사는 격리 SQLite와 임시 PostgreSQL 16 테스트 DB에서 수행했다. 진단 명령의 일반 공유 캐시 갱신은 허용했다.

## 1. 검색 품질

| 자료 종류 | 문항 | 운영 HTTP 상위 3개 적중 | 개선 코드 서비스 함수 적중 |
|---|---:|---:|---:|
| 매뉴얼 | 12 | 11/12 | 12/12 |
| 게시글 | 4 | 4/4 | 4/4 |
| 상품 | 4 | 4/4 | 4/4 |
| 합계 | 20 | **19/20 (95%)** | **20/20 (100%)** |

이 표의 개선 코드 수치는 같은 운영 자료에 관리 환경의 검색 함수를 직접 호출한 초기 결과다. 배포 후 운영 HTTP에서도 20/20을 확인했다(5절).

놓친 질문은 **“게시판은 어떻게 만드나요”**였다. 정답 「게시판 만들기」가 18위였다. 제목 토큰을 본문에 섞어 반복하는 기존 계산에서는 긴 본문의 길이가 제목 점수도 낮췄다. 제목과 본문에 각각 BM25를 적용한 뒤 `제목 점수 × 4 + 본문 점수`를 더하도록 바꿨다. 정답은 3위로 올라왔다. 질문별 분기나 정답 제목의 강제 우대는 추가하지 않았다.

일부 다른 질문은 1→2위, 2→3위로 바뀌었다. 전체 20문항은 상위 3개 기준을 충족하지만 이 작은 정답표만으로 모든 질문에 대한 품질을 보장할 수 없다. 고객 질문과 자료 종류를 추가해 평가를 확장해야 한다.

## 2. 운영 HTTP 속도 기준값

실행 환경에서 두 공개 사이트로 순차 GET 60회를 보냈다. 사이트별 요청 시작 간격은 2초, 질문별 최초 1회와 반복 2회다. DNT 헤더를 사용했고 로그인·클릭 API는 사용하지 않았다. 오류는 0건, 응답 리전은 icn1이었다.

| 사이트 | 최초 측정 수 | 최초 평균 / p95 | 반복 측정 수 | 반복 평균 / p95 |
|---|---:|---:|---:|---:|
| 데모 | 8 | 283.77 / 428.14ms | 16 | 264.28 / **337.04ms** |
| 핸드북 | 12 | 595.91 / 885.56ms | 24 | 532.95 / **581.45ms** |

여기서 최초는 도구의 첫 측정 회차다. 배포 함수가 새로 시작했는지 확인하는 계측이 없어 **실제 콜드 스타트 여부는 미확인**이다. 재배포·캐시 삭제로 인위적인 콜드 스타트를 만들지 않았다. 지연은 네트워크와 응답 읽기를 포함하며 작은 표본의 p95다. 동시 접속 부하나 대규모 자료의 처리량을 측정한 것은 아니다.

## 3. 병목과 개선

프로파일에서 후보 조회 SQL이 가장 오래 걸렸다. 활성 세대의 토큰과 순위를 여러 상관 서브쿼리에서 반복 조회했다. 모든 종류의 활성 세대가 준비된 경우에는 활성 스냅샷을 한 번 조인하도록 바꿨다. 세대는 SQL 안에서 현재 포인터를 읽으므로 재색인 전환 전에 읽은 세대 ID를 오래 보관하지 않는다. 초기 준비나 일부 종류만 세대 색인인 경우는 기존 호환 경로를 사용한다.

- 후보 조회 SQL 길이: 18,501→5,443자(같은 측정 질문).
- EXPLAIN 계획: 557→141줄. 작은 자료에서 순차 검색을 끈 인덱스 사용 가능 여부 검사이며, GIN 사용을 확인했다.
- 일반 저장·재색인·DB 스키마는 변경하지 않았다. 배포 시 새 마이그레이션이나 재색인이 필요 없다.

같은 프로세스·DB·질문에서 두 버전을 번갈아 5회씩 실행했다. 각 버전의 준비 호출은 제외했다.

| 질문 | 기존 평균 | 개선 평균 |
|---|---:|---:|
| 검색 | 390.53ms | 260.65ms |
| 게시판은 어떻게 만드나요 | 503.35ms | 292.79ms |

이 수치는 관리 프로세스의 검색 함수 시간이다. 배포 후 운영 HTTP p95 감소율로 해석하지 않는다. 네트워크·DB 부하가 변할 수 있으므로 배포 뒤 정답표와 HTTP 측정을 다시 실행해야 한다.

## 4. 권한·회귀 검사

제목·본문에 겹치지 않는 고유 표식으로 다음을 확인했다.

- 비회원·일반회원·작성자·관리자의 검색 결과와 전체 건수.
- 비밀글 제목 접근과 모든 역할의 비밀 본문 검색 제외.
- 비회원·미열람 회원의 유료 본문 검색·요약 제외.
- 순위 계산 뒤 권한이 철회된 자료의 응답 제외.
- 현재 페이지에 필요한 원문만 한 번 조회하고 길이를 제한하는지.
- 준비 중인 세대의 토큰이 활성화 전에 검색·건수에 나타나지 않는지.
- 일부 종류의 활성 세대가 없는 경우에도 권한이 적용되는 호환 검색.
- 긴 본문 때문에 제목 일치가 본문만 일치하는 글보다 밀리지 않는지.
- PostgreSQL GIN, SQLite 토큰 인덱스, 한국어 기존 평가·클릭·상품 정렬 호환.
- 측정 도구가 잘못된 응답과 HTTP 오류를 성공률·정상 지연에 섞지 않는지.

| 검사 | 결과 |
|---|---|
| SQLite 검색·권한·게시판/상품 검색 회귀 | 51개 실행, 성공(2개 PostgreSQL 전용 skip) |
| PostgreSQL 16 동일 회귀 | 51개 실행, 성공(1개 SQLite 전용 skip) |
| Ruff · Django check · migration drift · diff whitespace | 통과 |
| 현재 운영 자료로 개선 코드의 정답표 재평가 | 20/20 상위 3개 적중 |

초기 로컬 검사는 검색 관련 회귀에 한정했다. 이후 PR CI의 전체 프로젝트 테스트는 2,341개 실행, 성공(9개 skip), 커버리지 75%였다. 대규모 부하 검사는 수행하지 않았다. PostgreSQL 검사는 다른 서비스와 분리된 `127.0.0.1:55440`의 임시 컨테이너에서 실행했으며 완료 후 컨테이너와 임시 볼륨을 정리했다.

## 5. 운영 배포 후 확인

2026-10-21, 병합 커밋 `6987fdca0f239deb7dd134d807a20b78d8adb4a9`의 두 운영 배포가 READY인 것과 공개 도메인 연결을 확인했다. 리전은 모두 icn1이다. 새 마이그레이션이나 재색인은 실행하지 않았다. Preview 검색의 HTTP 200 및 `noindex, nofollow, noarchive` 헤더도 병합 전에 확인했다.

- 데모: `dpl_34d2Who5u64CNLcnDQbnz94M4sCQ`
- 핸드북: `dpl_7NYLMHV6V9cCGEsLvmQVfEvdf95M`
- [필수 CI 검사](https://github.com/thisgun/gnu-jango/actions/runs/39533441565): Django·Next.js·테마·Docker 통과. CodeQL도 통과.

같은 정답표·옵션으로 공개 HTTP 60회를 다시 측정했다. 최초 회차 상위 3개 적중은 **20/20(매뉴얼 12/12, 게시글 4/4, 상품 4/4)**, 세 회차 모두 각 질문의 정답이 상위 3개 안에 들었다. 요청 오류는 0건이었다.

| 사이트 | 최초 평균 / p95 (전→후) | 반복 평균 (전→후) | 반복 p95 (전→후) |
|---|---:|---:|---:|
| 데모 | 283.77 / 428.14→298.03 / 739.84ms | 264.28→207.39ms | 337.04→319.72ms |
| 핸드북 | 595.91 / 885.56→405.36 / 674.99ms | 532.95→317.28ms | 581.45→365.49ms |

반복 평균은 데모 약 22%, 핸드북 약 40% 줄었다. 데모의 최초 회차 평균·p95는 오히려 늘었다. 네트워크·연결 준비·캐시·DB 상태가 달라지는 별도 시점의 소규모 측정이며, 실제 콜드 스타트나 동시 접속 처리량을 검증한 수치는 아니다. 전체 사이트의 모든 요청이 빨라졌다고 해석하지 않는다.

메인 두 곳·쇼핑몰·정적 자산·검색 결과 상위 3개의 중복 없는 링크·점수 설명 API를 포함한 추가 GET 46회는 모두 HTTP 200이었다. 데모의 기본 테마와 핸드북 테마 표시를 확인했고, 공개 API에서 갱신한 BM25 설명도 확인했다.
