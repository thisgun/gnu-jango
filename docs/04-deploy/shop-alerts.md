# 쇼핑몰 알림 운영 안내 (가격 인하 알림 · 재입고 SMS 자동 발송 · 장바구니 알림 메일)

작성일: 2026-10-30

예약 작업 `send_shop_alerts` 하나가 세 가지 알림을 보낸다. **세 기능 모두 기본값은 꺼짐이다.** 쇼핑몰 설정에서 켜기 전에는 사이트가 이전과 똑같이 동작한다.

관련 문서: [백그라운드 작업](background-jobs.md), [실시간 알림](realtime-notifications.md).

## 켜는 곳

관리자 › 쇼핑몰 설정 › 기타 설정 › **알림·장바구니 메일**

| 설정 | 기본값 | 설명 |
| --- | --- | --- |
| 가격 인하 알림 (`de_price_alert_use`) | 꺼짐 | 상품 페이지에 알림 단추(종 모양)를 보인다. 회원만 신청할 수 있다. |
| 재입고 SMS 자동 발송 (`de_stock_sms_auto`) | 꺼짐 | 재고가 다시 생긴 상품의 재입고 알림 신청자에게 SMS를 자동으로 보낸다. SMS 설정(아이코드)과 쇼핑몰명·회신번호가 있어야 보낸다. |
| 장바구니 알림 메일 (`de_cart_reminder_use`) | 꺼짐 | 담아 두고 주문하지 않은 회원에게 메일을 보낸다. |
| 장바구니 알림 대기 시간 | 24시간 | 마지막으로 상품을 담은 뒤 이 시간이 지나야 보낸다. |
| 알림 쿠폰 할인금액 / 주문 최소금액 / 유효기간 | 0원 / 0원 / 7일 | 0원이면 쿠폰 없이 메일만 보낸다. |

메일은 기본환경설정의 메일발송 사용(`cf_email_use`)이 켜져 있어야 나간다.

## 무엇을 보내나

**가격 인하 알림.** 회원(탈퇴·차단 회원 제외)이 신청할 때의 가격을 기억해 두고, 상품이 그보다 싸게 판매 중(판매함, 품절 아님, 재고 있음)이 되면 메일과 사이트 알림을 **한 번** 보낸다. 다시 받으려면 상품 페이지에서 다시 신청한다(그때 가격이 새 기준이 된다). 목록: 관리자 › 가격 인하 알림.

**재입고 SMS 자동 발송.** 아직 한 번도 보내려고 하지 않은 신청 가운데 재고가 생긴 상품(재입고 알림 사용 상품, 품절 아님, 재고 1개 이상)의 것을 한 번에 25건까지 보낸다. 한 번 시도한 신청(실패 포함)은 자동으로 다시 보내지 않는다. 실패한 건은 관리자 › 재입고 알림에서 골라 직접 보낸다(기존 발송 동작과 같은 코드). 발송 기록: 관리자 › 재입고 SMS 발송 기록.

**장바구니 알림 메일.** 광고성 정보(정보통신망법 제50조)이므로 다음을 지킨다.

- **정보 메일 수신에 동의하고 메일 주소를 인증한 회원에게만** 보낸다. 회원가입 화면과 회원정보 수정 화면에 "정보 메일 수신" 항목이 있고 기본값은 받지 않음이다. 동의·해제한 날짜를 저장한다(`Profile.mailing_date`).
- 제목 앞에 `(광고)`를 붙이고, 본문에 동의한 날짜와 수신 해제 방법(회원정보 수정)을 적는다.
- 같은 장바구니(마지막으로 담은 시각이 같은 장바구니)에는 한 번만, 한 회원에게는 7일에 한 번까지만 보낸다.
- **08:00~21:00(서버 TIME_ZONE)에만** 보낸다. 야간 광고는 별도 동의가 필요해서(제50조 제3항) 밤에 대상이 된 장바구니는 아침 8시 이후 첫 실행에 보낸다.
- 메일을 보내지 못하면(메일 서버 오류 등) 그 기록과 쿠폰을 지우고 다음 실행에 다시 시도한다. 기본환경설정의 메일발송 사용이 꺼져 있으면 아예 기록하지 않는다.
- 담은 뒤에 주문한 회원, 탈퇴·차단한 회원, 바로구매로만 담긴 줄, 보관기간이 지난 줄에는 보내지 않는다. 비회원 장바구니는 메일 주소가 없어 대상이 아니다.
- 쿠폰을 설정하면 주문 할인 쿠폰("장바구니 알림 쿠폰")을 발행한다. 아직 쓰지 않은 알림 쿠폰이 있는 회원에게는 새로 발행하지 않는다.

발송 기록: 관리자 › 장바구니 알림 메일.

그누보드5에서 회원을 옮길 때(`migrate_gnuboard5`) `mb_mailling` 값을 정보 메일 수신 동의로 가져온다. 날짜가 따로 없으므로 옮긴 시각을 동의 날짜로 기록한다. 2년마다 수신 동의 여부를 알려야 하는 의무(정보통신망법 시행령 제62조의3)는 운영자가 메일 발송 기능으로 따로 챙긴다.

## 예약 작업

```powershell
python manage.py send_shop_alerts --json          # 보낼 건수만 센다 (dry-run)
python manage.py send_shop_alerts --apply --json  # 보낸다
```

`run_scheduled_jobs`와 Celery Beat 일정(`SCHEDULED_JOBS`, 600초 간격)에 들어 있다. Vercel 크론(`vercel.json`)은 하루 한 번(18:00 UTC = 03:00 KST)만 `/api/internal/cron`을 부르므로, 그대로 두면 장바구니 알림 메일은 매번 발송 시간(08~21시) 밖이라 나가지 않는다. Vercel에서 쓰려면 Supabase pg_cron 같은 외부 스케줄러가 낮 시간에도 같은 주소를 `Authorization: Bearer <CRON_SECRET>`으로 부르게 한다. 켜진 종류만 처리하고, 꺼진 종류는 결과에 `null`로 나온다. 한 번에 가격 알림 200건, SMS 25건, 장바구니 메일 100건까지 보낸다(`--limit`으로 줄일 수 있다).

## API

| 요청 | 설명 |
| --- | --- |
| `GET /api/v1/settings` | `price_alert_enabled`: 상품 페이지에 알림 단추를 보일지. |
| `GET/POST/DELETE /api/v1/shop/products/<it_id>/price-alert` | 회원의 가격 인하 알림 조회·신청·해제. 기능이 꺼져 있으면 신청은 409 `price_alert_disabled`. 분당 30회. |
| `GET /api/v1/shop/price-alerts` | 회원의 가격 인하 알림 목록(최근 200건). |
| `GET /api/v1/auth/me`, `PATCH /api/v1/members/me`, `POST /api/v1/auth/register` | `mb_mailling`(1/0)과 `mb_mailling_date`. |

## 데이터베이스

마이그레이션 `shop.0039_price_alerts_cart_reminders`(가격 인하 알림, 장바구니 알림 메일 표)와 `users.0016_profile_mailing`(회원 정보 메일 수신 동의). Vercel 데모처럼 migrate를 자동으로 돌리지 않는 배포는 코드를 올리기 전에 적용한다.
