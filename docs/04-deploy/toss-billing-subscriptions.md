# 정기구독 (토스페이먼츠 카드 자동결제) 운영 설정

회원이 상품 상세에서 배송 주기를 고르고 카드를 한 번 등록하면, 고른 주기마다 등록한 카드로 결제하고 일반 쇼핑몰 주문을 만듭니다. 기본은 꺼져 있고, 켜지 않으면 사이트에는 아무것도 바뀌지 않습니다.

코드: `gnu_jango/shop/subscriptions.py`(흐름), `gnu_jango/shop/toss_billing.py`(Toss API 호출), `gnu_jango/api/shop_subscriptions.py`(회원 API), `gnu_jango/shop/admin/subscriptions.py`(관리자).

## 켜는 순서

1. **토스페이먼츠 자동결제(빌링) 계약.** 라이브 자동결제는 일반 결제와 별도로 토스페이먼츠와 자동결제 계약을 맺어야 합니다. 계약 전 라이브 키로는 카드 등록창이 열리지 않거나 빌링키 발급이 거절됩니다.
2. **API 개별 연동 키.** 자동결제는 API 개별 연동 키(`test_ck_` / `test_sk_`, `live_ck_` / `live_sk_`)로만 됩니다. 결제위젯 키(`test_gck_` / `test_gsk_`)면 신청 단계에서 "카드 자동결제에는 토스페이먼츠 API 개별 연동 키가 필요합니다"로 거절합니다. 키는 일반 결제와 같은 곳(환경 변수 `SHOP_TOSS_CLIENT_KEY` / `SHOP_TOSS_SECRET_KEY` 또는 관리자 > 쇼핑몰 설정 > 결제설정)에서 읽습니다. 결제대행사가 NICEPAY인 쇼핑몰도 토스 키가 있으면 정기구독은 토스로 결제합니다.
3. **서버 허용.** `.env`에 `SHOP_SUBSCRIPTIONS_ENABLED=True`를 넣고 재시작합니다. 이 값이 켜져야 `run_scheduled_jobs`(및 Celery beat)에 결제 작업이 등록됩니다.
4. **관리자 스위치.** 관리자 > 쇼핑몰 설정 > 결제설정 > **정기구독 (카드 자동결제)**에서 `정기구독 사용`을 켭니다. 같은 곳에서 결제 예정 안내 일수(기본 3일 전)와 결제 실패 시 시도 횟수(기본 3회)를 정합니다.
5. **상품.** 상품 수정 > **정기구독** 탭에서 `정기구독 가능`을 켜고 고객이 고를 배송 주기(1주 · 2주 · 4주 · 매월)와 정기구독 할인율(0~50%, 상품 기본가에만 적용, 옵션 추가금액은 그대로)을 정합니다.

서버 허용과 관리자 스위치가 모두 켜진 동안만 상품 상세의 정기구독 칸, 마이페이지 > 정기구독 메뉴, 회원 API, 결제 작업이 동작합니다. 관리자 스위치를 끄면 새 신청과 자동결제가 모두 멈추고(기존 구독은 남음), 다시 켜면 밀린 결제일의 회차를 한 번 결제한 뒤 다음 주기로 이어집니다.

## 흐름

1. 상품 상세: 회원만 신청합니다. 옵션 하나와 수량, 주기, 저장된 배송지(마이페이지 > 배송지 관리)와 배송 메모를 고르면 `POST /api/v1/shop/subscriptions/start`가 카드 등록 대기 구독을 만들고 등록 토큰(30분, 한 번만)과 회원별 `customerKey`를 줍니다.
2. 브라우저가 SDK v2 `tossPayments.payment({ customerKey }).requestBillingAuth({ method: "CARD", successUrl, failUrl })`로 카드 등록창을 엽니다.
3. 성공 주소 `/shop/subscriptions/billing/success?token=…`에 Toss가 `customerKey`, `authKey`를 붙입니다. 이 화면이 `POST /api/v1/shop/subscriptions/billing-auth`로 넘기면 서버는 토큰이 그 회원의 대기 중 등록인지, `customerKey`가 같은지 확인한 뒤 `POST /v1/billing/authorizations/issue`로 빌링키를 받습니다.
4. 빌링키는 `SECRET_KEY`로 봉인(`shop/sealed_values.py`)해 구독에만 저장하고 브라우저 · 관리자 화면 · 로그 어디에도 내보내지 않습니다. 카드는 Toss가 준 카드사(`card.issuerCode`)와 마스킹된 번호만 보여 줍니다.
5. 곧바로 1회차를 결제합니다. 첫 결제가 거절되면 구독을 시작하지 않고(해지 · 빌링키 삭제) 주문도 취소합니다.

`customerKey`는 회원마다 한 번 만드는 무작위 값(`gj_` + 32자)입니다. 회원 아이디 · 이메일 · 번호를 쓰지 않습니다(Toss: 유추 가능한 값은 안전하지 않음).

## 결제 한 회차

결제 작업(`charge_shop_subscriptions`)과 첫 결제는 같은 함수를 씁니다.

1. 구독 행을 잠그고(`select_for_update`) 이번 회차의 결제 행을 만듭니다. 데이터베이스 제약이 회차마다 결제 중 · 완료 · 확인 필요 행을 하나만 허용하므로, 다시 실행하거나 두 작업이 동시에 돌아도 같은 회차를 두 번 결제하지 않습니다.
2. 결제하는 날의 상품 가격(할인 적용)으로 체크아웃과 같은 주문 생성 코드(`create_order_from_lines`)가 `주문` 상태 주문을 만들고 재고를 잡습니다. 재고가 없거나 판매 중지 · 품절이면 이번 회차는 **건너뛰고** 다음 주기로 넘어가며 회원에게 알립니다. 상품이 삭제되면 일시정지합니다.
3. `POST /v1/billing/{billingKey}`로 금액을 승인합니다. 금액은 서버가 계산한 주문 금액이며 브라우저 값은 쓰지 않습니다. 시도마다 따로 만든 `Idempotency-Key`를 보내므로 같은 요청이 다시 가도 Toss는 한 번만 처리합니다.
4. 승인되면 체크아웃 결제 확인과 같은 `confirm_order_payment`로 주문을 `입금`으로 바꿉니다(주문 메일 · SMS · 결제 로그 · 포인트 규칙 그대로). Toss 승인 주문번호 · 금액이 맞지 않으면 결제 행을 **확인 필요**로 두고 주문은 그대로 둡니다.
5. 거절되면 주문을 취소해 재고 · 쿠폰 · 포인트를 돌려놓고 다음 날 다시 시도합니다. `결제 실패 시 시도 횟수`만큼 실패하면 구독을 일시정지(결제 실패)하고 회원에게 메일과 알림을 보냅니다. 회원이 카드를 바꾸고 다시 시작하거나, 관리자가 재시도할 수 있습니다.
6. 응답을 받지 못하면(네트워크 오류 · 5xx) 결제 행을 결제 중으로 둡니다. 다음 작업이 10분 넘은 결제 중 행을 `GET /v1/payments/orders/{orderId}`로 조회해 승인됐으면 완료, Toss에 결제가 없으면 실패로 처리합니다. 첫 결제가 이렇게 실패로 확인되면 구독을 해지하고 알립니다. 승인됐지만 확인 필요가 된 결제는 paymentKey를 주문에 남겨 미결제 주문 자동 취소에서 빠지고 주문 취소로 환불할 수 있습니다.

알림(메일 + 사이트 알림)은 결제 예정(안내 일수 전, 회차마다 한 번), 결제 완료, 결제 실패, 일시정지, 건너뜀, 해지 때 보냅니다. 결제 금액이 결제일 가격으로 정해진다는 안내는 상품 상세, 결제 예정 메일, 마이페이지에 모두 표시합니다.

## 결제 작업 실행

`SHOP_SUBSCRIPTIONS_ENABLED=True`이면 `run_scheduled_jobs`가 1시간마다 `charge_shop_subscriptions --apply --json --limit 50`을 실행합니다(한 번에 최대 50건, 나머지는 다음 시간). 승인 한 건이 최대 60초 걸릴 수 있습니다.

```powershell
# 오늘 결제할 구독 수만 셉니다(데이터베이스 · Toss에 쓰지 않음)
python manage.py charge_shop_subscriptions --json
# 실제 결제
python manage.py charge_shop_subscriptions --apply --json
# 특정 날짜 기준으로(밀린 날짜 점검)
python manage.py charge_shop_subscriptions --date 2026-11-01 --json
```

출력의 `charged` · `failed` · `skipped` · `pending` · `review`를 보고, `review`가 있으면 관리자 > 정기구독 결제에서 확인합니다.

## 관리자

- **정기구독**: 상태 · 주기 · 결제 실패 사유로 거르고, 선택한 구독을 일시정지 · 해지(빌링키를 Toss에서도 삭제) · 지금 결제 재시도(이번 회차 결제가 실패했거나 결제 실패로 일시정지된 구독만, 결제일 전 회차를 앞당겨 결제하지는 않음)합니다. 관리자가 일시정지한 구독은 회원이 다시 시작할 수 없습니다. 삭제는 막혀 있습니다(해지를 쓰세요).
- **정기구독 결제**: 회차별 결제 행과 주문 링크. 실패한 최근 회차는 `실패한 결제를 지금 다시 시도`로 재시도합니다.
- **환불**: 정기구독 결제로 만든 주문은 일반 카드 주문입니다. 주문 화면의 취소 · 부분취소가 그 주문의 키 쌍(`od_test`)으로 Toss 결제 취소 API를 부릅니다. 주문을 취소해도 구독은 계속되므로, 그만 보내려면 구독도 해지하세요.

## 테스트 키로 확인

- 테스트 키에서는 실제로 결제되지 않습니다. 본인인증 창이 뜨면 인증번호 `000000`을 넣습니다. 테스트 환경은 카드번호 앞 6자리(BIN)만 유효하면 됩니다.
- 거절 상황은 Toss 테스트 헤더(`TossPayments-Test-Code`, 예: `INVALID_REJECT_CARD`)로 재현할 수 있습니다(테스트 키에서만 동작). 이 저장소의 테스트는 Toss를 부르지 않고 `gnu_jango/shop/toss_billing.py`를 바꿔 끼웁니다(`gnu_jango/core/test_shop_subscriptions.py`).
- 결제 테스트(테스트 · 실결제 키 쌍)를 바꿔도, 이미 등록된 카드는 등록할 때의 키 쌍으로 결제 · 환불합니다(`toss_mode` / 주문 `od_test`). 실결제로 넘어가면 테스트 키로 등록한 구독은 카드를 다시 등록해야 합니다.

## 라이브 전환 점검

1. 토스페이먼츠 자동결제 계약과 API 개별 연동 라이브 키를 확인합니다.
2. 테스트 키로 신청 → 첫 결제 → 주문 `입금` → 마이페이지 표시 → 건너뛰기 · 일시정지 · 해지를 한 번씩 확인합니다.
3. `charge_shop_subscriptions --date <다음 결제일> --apply --json`으로 정기 결제와 실패 · 재시도를 테스트 키에서 확인합니다.
4. 라이브 키로 바꾸고 소액 상품으로 첫 결제와 환불(주문 취소)을 확인합니다.
